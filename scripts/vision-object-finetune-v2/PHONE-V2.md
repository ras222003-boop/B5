# اختبار كاميرا V2 والهاتف: حدود الدليل

يختبر `camera_probe.py` مصدر كاميرا Windows مباشرًا عبر DirectShow أو MSMF،
واستدلال ONNX Runtime الأصلي على CPU. لا يحفظ بكسلات الكاميرا أو الصوت، ولا
يرفع الوسائط. يحتفظ بالأزمنة والمربعات وملخص الإضاءة فقط. اختلاف معالجة
OpenCV عن Canvas يعني أن أزمنته ومخرجاته لا تمثل أداء Safari أو صفحة بصيرة.

يختبر `physical-camera-browser.mjs` صفحة بصيرة القائمة، مع `getUserMedia`
الأصلي ودون معاملات أجهزة مزيفة أو استبدال مصدر الفيديو. يربط اسم المسار
الحي بقائمة كاميرات USB في Windows، ويسجل التوقف والإطارات والأداء وذاكرة
عائلة عمليات Chrome. يُوقف النص الصوتي المسموع في أداة الاختبار، لذلك لا
يثبت جودة النطق المسموع. لا يحفظ صورًا أو لقطات شاشة من الكاميرا الفعلية.

تظل دقة الكشف في هذه اللقطات الحية غير محسوبة دون مرجع مستقل للمشهد. فحص
الحركة والإضاءة وقراءة الإطار يثبت وصول مصدر حي، ولا يحول التوقعات إلى وسوم
مرجعية. يجب الفصل بين معدل التحليل وإطارات العرض المتخطاة عمدًا أو الساقطة.

```powershell
./.metric-venv/Scripts/python.exe scripts/vision-object-finetune-v2/camera_probe.py --output ../.vision-test-fixtures/object-finetune-v2-001/camera/native-v2-001.json --model objects-basira-v2=../.vision-test-fixtures/object-finetune-v2-001/training/basira_objects_v2.onnx --seconds 12
node scripts/vision-object-finetune-v2/physical-camera-browser.mjs http://127.0.0.1:4350 ../.vision-test-fixtures/object-finetune-v2-001/camera/browser-v2-001.json objects-basira-v2
```

كل ناتج دليل جديد؛ لا تستبدل ناتجًا سابقًا. توجد مهلة خارجية لإنهاء التقاط
OpenCV العالق. إذا كان مصدر الإطار أسود أو موحدًا، أو لم يفتح الجهاز، يسجل
ذلك ولا يُعلن نجاح تقييم الكاميرا. مطابقة فهرس OpenCV لاسم جهاز Windows
غير مؤكدة دون فحص المتصفح، فلا تعتمد قائمة USB وحدها دليلًا لهذه المطابقة.
إذا تقدمت timestamps وعدادات العرض لكن ظلت بصمة البكسلات بعد الإحماء
ثابتة، يسجل المصدر `STATIC_SCENE_UNVERIFIED`: قد يكون مشهدًا ثابتًا أو
تدخّل خصوصية/برنامج تشغيل، ولا يمكن الجزم بالسبب من القياسات وحدها. فتح
مسار جهاز فعلي لا يكفي لإعلان نجاح تقييم الأشياء الواقعي أو الحركة.

## تجهيز iPhone دون ادعاء تنفيذه

### ما تحقق على الحاسوب في هذه الجولة

- عُثر على كاميرتي USB باسم ASUS FHD webcam وASUS IR camera. أكد مسار
  `getUserMedia` داخل بصيرة استعمال ASUS FHD webcam نفسها، بدقة1920×1080
  ومعدل مصدر15 إطارًا/ثانية، دون مصدر مزيف أو مسارات صوت.
- بقيت إطارات تجربة DirectShow الأولى متطابقة بعد الإحماء، وكذلك ملخصا
  تجربة المتصفح الأولى؛ حُفظ ذلك ولم يُعد نجاحًا في تقييم مشهد متغير.
  محاولة MSMF منفصلة لم تفتح مصدرًا؛ لم يُحسم السبب.
- بعد أن فتح المستخدم الغطاء وحرّك الجسم، تغيرت بصمتا العينة وملخصا
  الإضاءة بوضوح في `browser-tiny-003-user-movement.json`. نفذ Tiny
  عشرين تحليلًا خلال10.018 ثانية، أي نحو2.00 تحليل/ثانية. قيمةP95 الدورية
  كانت533ms وتشمل بدء الجلسة؛ ليست زمن ONNX وحده. بلغ RSS عائلة Chrome
  نحو1141.6MiB بعد التحليل مقابل966.5 قبل تشغيل الكاميرا.
- أبلغ عداد المتصفح عن150 إطار عرض ساقطًا من151 إطارًا متاحًا في القياس
  نفسه. لا نساوي هذا العداد بالإطارات غير المحللة عمدًا، ولا ندعي سلاسة
  المعاينة أو نشخص سببه من هذا الاختبار. نجح إيقاف المسارات فعلًا.
- الاستدلال الأصلي Native ORT على إطارات تجربة DirectShow الأولى أعطى
  وسيطًا/P95 نحو98.9/127.4ms لـTiny و98.4/114.2ms لـV1؛ مصدرها بقي ثابتًا
  بعد الإحماء، والمعالجة مختلفة عن المتصفح. لا تُقرأ كدقة أو تفوق نسخة.

يجمع `camera/qualification-baseline-v1.json` هذه الحدود وبصمات الأدلة
الأصلية. لم يحفظ أي تصوير خام أو لقطات شاشة، ولم ترفع وسائط. ليست لهذه
اللقطات الحية مراجع أجسام مستقلة، لذلك بقيت الدقة `null`. اختبار V2
الفعلي يُجرى بعد وجود وزنه المسجل، ولا يُستنتج من نجاح Tiny.

نجحت أربعة اختبارات Python لتصنيف دليل الكاميرا، وأربعة اختبارات Node
لمنع المضيفات العامة أو الشبيهة بعنوان خاص في preflight. لا تفتح هذه
الاختبارات الوحدوية كاميرا، ولا تعد بياناتها الاصطناعية دليل جهاز.

```powershell
./.metric-venv/Scripts/python.exe scripts/vision-object-finetune-v2/test_camera_probe.py
node --test scripts/vision-object-finetune-v2/phone-preflight.test.mjs
```

### حالة الهاتف

`iphone-trial-template.json` قالب بحالة `NOT_RUN`، وليس نتيجة اختبار. توضع
بصمة ONNX الفعلية فيه بعد اكتمال التدريب. لا تُملأ أرقام الهاتف أو الذاكرة
من قياسات الكمبيوتر، ولا يُسمى Chrome بعرض ضيق اختبار Safari.

الرابط الحالي HTTP/loopback؛ واجهة أصول النماذج ترفض LAN. يلزم أولًا إعداد
أصل HTTPS محلي موثوق مع وصول مصادق ومصرح به إلى **صفحة بصيرة نفسها**
وأصولها. لا يعد تشغيل مختبر السلالم المنفصل اختبارًا لهذه الصفحة.

يمكن إعادة استخدام helper الشهادات الموجود في `scripts/vision-ai/camera-lab`
بعد تهيئة الأصل والوصول: انقل الشهادة العامة فقط، وراجع البصمة وثقة الجهاز
مع مالكه أو مسؤول أجهزته. لا تنقل المفاتيح الخاصة ولا تغير جدار الحماية أو
مخزن الثقة أو إعدادات Norton آليًا.

وثقت الجولة القديمة استبدال Norton شهادة HTTPS بشهادة غير موثوقة. هذه
معلومة تاريخية حتى يُعاد الفحص على الاتصال المقصود. يقرأ
`phone-preflight.mjs` الشهادة العامة ويستخدم `rejectUnauthorized=true`؛ لا
يُفعّل `NODE_TLS_REJECT_UNAUTHORIZED=0` ولا يتجاهل أخطاء الشهادات. يثبت
التحقق من السلسلة واسم المضيف قبل طلب الكاميرا. إذا اعترضت سلسلة غير مصرح
بها، أبقِ التحقق مفعّلًا وراجع مسؤول الحماية أو استخدم بيئة محلية معتمدة
تمرر سلسلة الشهادة المصرح بها، دون تعطيل الحماية.

```powershell
node scripts/vision-object-finetune-v2/phone-preflight.mjs --origin http://127.0.0.1:4350 --output ../.vision-test-fixtures/object-finetune-v2-001/camera/phone-preflight.json
# فقط بعد إعداد HTTPS المصرح والشهادة العامة:
node scripts/vision-object-finetune-v2/phone-preflight.mjs --https-url https://PRIVATE_IP:PORT/navigation/vision --ca PATH_TO_PUBLIC_ROOT_CERTIFICATE --output NEW_PREFLIGHT_EVIDENCE.json
```

عند الاختبار الفعلي: سجّل الجهاز وإصدار iOS/Safari والدقة والإضاءة ومصدر
المشهد المصرح، ثم زمن التحميل ووسيط/P95 ومعدل التحليل والإطارات المتخطاة
والحرارة والإيقاف والرجوع إلى Tiny وLite0. تظل الذاكرة `null` إن لم يوفّر
Safari طريقة موثوقة لقياسها. لا توجد أهلية ملاحية أو أقنعة ألوان في التجربة.
