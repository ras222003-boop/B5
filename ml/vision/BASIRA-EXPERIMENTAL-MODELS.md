# النماذج البحثية داخل رؤية بصيرة

أصبح V3 متاحًا **داخل الصفحة الأصلية** `/navigation/vision`، وليس داخل خادم
مختبر آخر. تعرض قائمة «نموذج الرؤية» المزود الأصلي والإصدارات التجريبية المحلية
التي اجتازت الفحص. يبقى الأصلي افتراضيًا، بما في ذلك بعد إعادة تحميل الصفحة.
تحدّث القائمة كل 15 ثانية؛ لا تختار نموذجًا جديدًا أو تفتح الكاميرا تلقائيًا.

## الاستخدام المحلي الحالي

شغّل بصيرة من جذر B5، لا خادم camera-lab:

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 4340 --strictPort
```

افتح `http://127.0.0.1:4340/navigation/vision`، واختر
`basira-stairs-v3-research — تجريبي`. بعد تأكيد صلاحية الاستدلال، اختر الكاميرا
أو صورة أو فيديو. تبقى الوسائط في المتصفح. تظهر المربعات والاتجاه أو عدم
اليقين وثقة غير معايرة وزمن تجهيز/استدلال وعدد الإطارات. يمكن تصدير JSON
بالتوقعات دون الوسائط. الملفات محدودة بـ512 MiB والجلسة بـ10000 نتيجة.

زر الرجوع يوقف الكاميرا والعامل والطلبات قيد التحميل وObject URLs، ويعيد
واجهة المزود الأصلي؛ تشغيل كاميرته يظل إجراءً صريحًا. التبديل أثناء التحميل
لا ينتظر انتهاء النموذج البحثي. تُرفض البايتات المعدلة أو العقد الخاطئ مع
بقاء خيار الرجوع متاحًا. النموذج الأصلي ليس نموذج سلالم مُحسّنًا بهذا العمل؛
لم تتغير أوزانه أو خرائط فئاته.

## المحول وحدود السلامة

ينفذ `ExperimentalStairsProvider` عقد `VisionProvider` القائم ويعيد
`VisionDetection` بمربعات normalized xywh. يعيد استخدام محول V3 من
`scripts/vision-ai/camera-lab/adapter.mjs` عبر تعريفات TypeScript؛ لا توجد
نسخة مستقلة قد تختلف في letterbox أو اتجاهات الفئات. الإدخال RGB/NCHW160
والحشو127، ومخرجات الحضور والاتجاه والمربع مطابقة للـONNX الفعلي.

يشغّل عامل مخصص ONNX Runtime Web/WASM بخيط واحد ويعزل إعداداته عن محرك
المسافات الأصلي. يتحقق من SHA-256 وأسماء/أبعاد tensors والقيم المنتهية. خدمة
`CameraService` القائمة تدير كاميرا بصيرة. يلتقط العرض إطارًا قبل الاستدلال
ويرسم النتيجة على الإطار نفسه، دون ادعاء أن الصورة القديمة بث حي بعد الإيقاف.

تحتوي الكشوف على `experimental.navigationEligible:false` و
`referenceLabel:false` ووسم `EXPERIMENTAL_DISPLAY_ONLY`. ترفض `VisionPipeline`
إدخال هذا المزود، وترفض أي كشف بحثي يعبر حدها من مزود آخر؛ كما يرفض محرك
السلامة تصنيفه. يبقى مسار العرض التجريبي في صفحة الرؤية خارج OCR والتوجيه
وتقدير الاقتراب والمسافات والتنبيهات. لا يوجد استدعاء كلام أو اهتزاز أو
إنذار سقوط في المكوّن البحثي. الاتجاه غير الكافي يبقى `STAIRS_UNCERTAIN`؛
السلم الكهربائي يحتفظ بفئته2304 في metadata والعرض، ويُمثل كجسم غير مصنف في
عقد الأنواع العام بدل اختراع أنه درج ثابت. لا يمر إلى تقدير المخاطر.

التعرف لا يكتب صورًا أو وسومًا أو سجلات حقوق أو موافقات إلى التدريب.
إدخال التدريب يظل إجراء Studio منفصلًا مع الحقوق والوسوم المرجعية والمراجعات
المطلوبة. تصدير التوقعات لا يجعلها ground truth. لم يُنفذ تدريب V4 أو تقييم
واقعي جديد في هذا الربط.

## السجل المحلي والتسجيل التلقائي

السجل الخاص الافتراضي `.vision-ai/experimental-models/` مستثنى من Git، ولا
توضع أوزانه داخل `client/public` أو `dist`. API القراءة المحلي يعرض metadata
المسموح بها وentry نظيفًا وONNX فقط؛ لا يعرض المسارات الخاصة أو checkpoint
أو سجلات الحقوق ولا يملك مسار رفع أو تسجيل عبر HTTP. يرفض Origin/Host غير
المناسبين ويحترم بوابة Basic Auth للمعاينة الخاصة إن كانت مضبوطة.

بعد نجاح `synthetic-stairs/train_v3.py`، ينفّذ الخطاف
`experimental-models/complete-v3.mjs` تلقائيًا. يتحقق من manifest الاصطناعي
وفحص البيانات وبصمات الأدلة وسلسلة أوزان المشروع ذات البدء العشوائي؛ لا
يولد موافقة على بيانات أو أوزان خارجية. يكتب `model.completion.json`، ثم:

1. يتحقق من اكتمال التدريب ووجود optimizer steps وتغير الأوزان وتقرير تصدير
   وparity ناجح، ونتائج تحقق/اختبار غير فارغة مرتبطة بالنموذج والبيانات.
2. يرفض أي عقد غير مدعوم. المحول الحالي يدعم عائلة السلالم ذات الرؤوس
   الثلاثة والمدخل160؛ أي معمارية أخرى تحتاج محولًا وفحصًا خاصين قبل إتاحتها.
3. ينفّذ ONNX checker وفحصًا فعليًا بـONNX Runtime على CPU مع إدخالين، ويتحقق
   من الأسماء والأبعاد والنوع والقيم المنتهية والمربعات. الحد64 MiB للملف،
   وخيطا CPU، ومهلة30 ثانية. يرفض البيانات الخارجية وcustom op domains.
4. ينسخ الإصدار إلى مجلد مؤقت ثم يعتمده بعملية rename، مع ID غير قابل
   للاستبدال وبصمات model/entry/completion. لا تختار بصيرة الإصدار تلقائيًا.

فشل التسجيل يحفظ التدريب وأوزانه ويكتب سببًا في
`experimental-registration.json`؛ لا يتجاوز الفحص أو يحوّل الفشل إلى نجاح.
عند اكتمال التدريب قبل اختبار مستقل، تكون إتاحة الإصدار **تحققًا تطويريًا
فقط** وتظهر كذلك في بصيرة. لا يدعي هذا وجود اختبار مستقل. الإتاحة التجريبية
ليست قبولًا للأداء؛ يبقى مستوى الثقة والمعايير والقصور ظاهرًا في metadata.

لربط أي منتج تدريب آخر بالبروتوكول، يصدر ملف `.completion.json` بحقول
`scope:basira-experimental-training-completion` و`status:completed` وID
ومراجع relative path/SHA-256 لـentry وتقرير التدريب والتقييم وprovenance،
مع `productionEligible:false` و`humanApproval:false`. يسجل CLI الإصدار المتوافق:

```powershell
node scripts/vision-ai/experimental-models/cli.mjs register '<completion.json>' --python '<existing-python.exe>'
node scripts/vision-ai/experimental-models/cli.mjs watch --inbox '<completion-folder>' --python '<existing-python.exe>'
node scripts/vision-ai/experimental-models/cli.mjs list
```

المراقب اختياري محلي، يعرض أسباب الرفض، ولا يعيد التحقق المكلف من إصدار ثابت
اجتاز الفحص دون تغير بايتاته. لا يفترض أن كل نموذج عام متوافق تلقائيًا.
للأوزان/البيانات الخارجية يلزم `reviewed_external` وسجل مراجعة حقوق مستقل
مربوط ببصمته؛ لم يُنشأ مثل هذا الاعتماد في هذه المهمة.

أسماء الحقول والتطبيق المرجعي موجودة في `complete-v3.mjs` و`registry.mjs`.
اختر `--registry` أو `BASIRA_EXPERIMENTAL_MODELS_ROOT` لمسار خاص آخر. الملفات
والـIDs المثبتة لا تُستبدل عند ظهور تقرير اختبار لاحق؛ استخدم descriptor وID
جديدين للمراجعة اللاحقة بدل إعادة كتابة تاريخ الإصدار.

## V3 المسجل والاختبارات الفعلية

سُجل V3 الحالي بعد فحص CPU جديد، وببصمة:
`a16132720922738e2cc3d248b84af5c1d92c6c9d97bc757d07867b3861ef0061`.
مرجع أدائه هو الاختبار الاصطناعي المستقل السابق: 144 صورة/32 مشهدًا،
F1 للدرج0.747، و24 إنذارًا كاذبًا و18 درجًا فائتًا. لا يوجد دليل واقعي جديد.
تأكد أيضًا أن إعادة مسح completion لا تكرر الإصدار أو ترفعه للإنتاج.

اختبار Chrome داخل `/navigation/vision` شغّل النموذج الفعلي على صورة
اصطناعية وفيديو اصطناعي وكاميرا مزيفة، وحفظ screenshot وJSON محليًا. اختبر
غياب كلام/اهتزازات البحث، وإيقاف المسارات، والرجوع وتشغيل EfficientDet الأصلي
فعليًا، ورفض نموذج معدل، وافتراضية الأصلي بعد reload. لم تُرفع وسائط أو
تُدخل إلى التدريب. حُجبت طلبات الخط/الشعار الخارجية القائمة في الموقع أثناء
الاختبار؛ ليست خدمة استدلال، ولا أرسل لها هذا المسار أي إطار. لا تثبت هذه
الاختبارات أداء كاميرا حقيقية أو iPhone أو صلاحية ملاحية.

```powershell
node --test scripts/vision-ai/experimental-models/registry.test.mjs
node node_modules/vitest/vitest.mjs run client/src/lib/vision/experimentalStairs.test.ts server/experimentalModels.test.ts
node scripts/vision-ai/experimental-models/basira-browser-test.mjs http://127.0.0.1:4340 '<private-evidence-folder>'
```

## الإنتاج والهاتف

الإتاحة الحالية Windows/loopback. لا يقبل API طلبات LAN أو تنزيلات عامة.
مسار خادم الإنتاج يعيد قائمة تجارب معطلة افتراضيًا؛ يتطلب تمكينه المحلي
صراحة `BASIRA_ENABLE_EXPERIMENTAL_MODELS=1`، مع استمرار رفض LAN. لا يغير هذا
المتغير النموذج الافتراضي ولا يمنح قبولًا إنتاجيًا أو ملاحيًا. لا يحتوي هذا
التغيير على عملية ترقية نموذج بحثي إلى production أو تزوير توقيع بشري.

يتطلب النشر أو توسيع الوصول للهاتف مراجعة مستقلة لصلاحيات الوصول وHTTPS
والخصوصية، وتقييمًا واقعيًا واعتمادًا مناسبًا قبل أي استخدام إنتاجي. عائق
شهادة Norton السابق لم يُعالج بتعطيل أو تجاوز؛ لم ينشر هذا العمل تطبيقًا أو
يفتح نفقًا أو يعدّل جدار حماية أو يدمج PR.
