# إصلاح حفظ الوسوم — 2026-10-16

الفرع المحلي: codex/basira-smart-prereview. لم تُدفع التعديلات أو تُدمج أو تُنشر. بقيت الأعمال السابقة محفوظة.

## السبب المثبت

أعيد إنتاج الخلل في Chrome بمكتبة وحساب annotator اصطناعيين. أعاد الخادم 400 مع Decision reason required عند غياب السبب، و409 مع Revision conflict; refresh before saving عند تحديث العينة من جهة أخرى مع بقاء إصدار المحرر قديمًا. وأعيد اختبار 400 Invalid class or bounding box لبيانات هندسية غير صالحة؛ لم تُلغ فحوص الصلاحية.

كانت refresh تعود فورًا إذا كان التحديث الدوري جاريًا، ثم يعيد مسار الحفظ فتح نسخة catalog القديمة بدل نسخة العينة المحفوظة. كما أن تحديث المكتبة لا يجدد قاعدة المحرر المفتوح، ولا يوجد قفل للحفظ المتكرر. رسالة الفشل العامة كانت خارج dialog، فلا توفر للمحرر سببًا دائمًا ظاهرًا.

## التغيير

- جلب إصدار العينة مباشرة من الخادم عند الفتح وقبل الحفظ، مع version وbaseHash وبصمة الصورة في طلب الكتابة.
- ربط refresh الجارية بوعد قابل للانتظار، ومنع نتائج التحديث السابقة من استبدال حالة أحدث بعد الحفظ أو تبديل الجلسة.
- التقاط نسخة ثابتة من التعديلات والسبب، وحظر طلبات الحفظ المتزامنة وتجميد الحقول والتنقل أثناء الطلب.
- توفيق ثلاثي بين قاعدة التحرير والمسودة والإصدار الحالي. تندمج التعديلات غير المتداخلة فقط. المتعارضة تبقى مسودة وتعرض مقارنة وتحتاج اختيارًا صريحًا، دون حفظ تلقائي أو حذف سجل سابق. تغير الصورة أو الفهرس يمنع نقل المسودة آليًا.
- عرض HTTP وسبب الخادم الحقيقي داخل المحرر، مع إبقاء الحقول والسبب عند الفشل. التحقق من طول السبب قبل إرسال الطلب. تبقى المسودة في ذاكرة الجلسة عند التنقل، ويظهر تحذير المتصفح قبل مغادرة صفحة فيها تعديلات غير محفوظة؛ لا تُحفظ في السحابة أو localStorage.
- منع تحرير حقول الوسوم بحساب المراجع الذي لا يملك annotator؛ بقيت قيود استقلال جميع المساهمين ومراجعة الحقوق والخصوصية والوسوم في الخادم.

## الإثبات

نجح 65 اختبار Node مستهدفًا. وفي Chrome فعلي: أربع ضغطات أرسلت POST واحدًا، وتأخير استجابة التحديث الدوري القديمة حتى ما بعد الحفظ لم يرجع الإصدار إلى الوراء. حُفظ مربع معدل وجسم مرسوم جديد، ثم أعيد فتح الصورة والتحقق من القيم وهوية المحرر والسبب والطابع الزمني.

اختُبرت حالات متعمدة لـ400 و409، وبقيت المسودة والسبب؛ نجحت إعادة الحفظ بعد التصحيح/التوفيق. أعيد تشغيل خادم المكتبة الاصطناعية على المنفذ نفسه وأعيد اختبار الحفظ والاسترجاع في Chrome. وصلت سلسلة الاختبار إلى 11 إصدارًا، بما فيها مراجعة منفصلة بحساب مراجع اصطناعي؛ بقيت الحقوق والخصوصية معلقتين. في مسار النجاح: صفر أخطاء Console أو Network أو pageerror، وصفر اتصالات خارجية.

أعيد تشغيل الخادم الحقيقي على 127.0.0.1:4318 بعملية واحدة PID 6752، وفُتحت صفحة الدخول وملفات JavaScript في Chrome دون أخطاء. لم نسجل الدخول بحساب فعلي أو نعدل عينة حقيقية. تحققنا من دور basira-annotator-02 وامتلاك basira-owner أدوار المراجعة واستقلاله عن المساهمين الحاليين دون استعمال كلمات مرورهما. تطابقت بصمات 64 أصلًا وصورها النشطة والحسابات وسجل الإصدارات ونموذج EfficientDet قبل إعادة التشغيل وبعدها.
