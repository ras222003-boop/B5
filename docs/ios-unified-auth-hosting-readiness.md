# تحقق الدخول والاستضافة لتطبيق بصيرة الموحد — 30 أكتوبر 2026

هذا المستند مكمل لـ[تقرير الوظائف](ios-unified-basira-feature-audit.md)، ويصف فرع PR #58 فقط. لا يعني نجاح الاختبارات أن تسجيل الدخول على iPhone أو أي مستشعر اختُبر فعليًا.

## نتائج هذه الجولة

- استُعيد متصفح Codex، وبقي PR #58 مسودة. اكتمل فحصا الويب وiOS للالتزام `5cbfaf2c2f66fc19250b1a5f6003630f280a0f00` بنجاح: [الويب](https://github.com/ras222003-boop/B5/actions/runs/40899482042/job/123537522518)، [المحاكي](https://github.com/ras222003-boop/B5/actions/runs/40899495836/job/123537570004).
- أعاد النطاق المعتمد `/api/readiness` JSON بحالة `READY` و`optionalModels: DEGRADED`، وبقي `/api/vision/object-quality/manifest` يعيد `API endpoint not found`. لا تكشف الاستضافة SHA؛ لا تُنسب إليها شيفرة PR #58.
- تأكد من واجهة Codemagic أن `BASIRA_IOS_WEB_ORIGIN` محفوظ بالقيمة المعتمدة في مجموعة `basira_unified_ios`. لم تُعدّل القيمة ولم يُشغّل بناء. يعرض محرر `main` إعدادات أقدم؛ لا يُستخدم لتشغيل هذا الفرع.
- عرض `/account` نموذج تسجيل الدخول ولم يعرض جلسة بصيرة مؤكدة. بدأت محاولة Google من زر المنصة؛ رفضت مراجعة الموافقة التلقائية الاطلاع على نطاق Google لأن الموافقة السابقة لم تشمل هذا الانتقال تحديدًا. طُلبت موافقة محددة من المالك، ولم يُتجاوز الرفض أو تُدخل بيانات دخول أو تُقبل صلاحيات.

## إصلاحات الشيفرة

1. لم تعد علامة `?auth=success` إثباتًا للدخول. تنتظر الواجهة انتهاء جلب الجلسة وإعادة التحقق، وتتطلب مستخدمًا فعليًا دون خطأ؛ تعرض حالة غير مؤكدة عند فقد الجلسة أو خطأ التحقق. تُرفض العلامات المكررة والملتبسة، ويُمحى إشعار العودة السابق عند بدء دخول أو خروج صريح. أضيفت18 حالة اختبار ونصوص عربية وإنجليزية وصينية.
2. يتحقق `server/authOrigins.ts` من `BASIRA_PUBLIC_URL` كأصل HTTPS عام صريح، ويرفض بيانات الدخول والمنافذ والمسارات والاستعلامات والشظايا والعناوين المحلية والملتبسة. تبقى أسماء loopback مسموحة في التطوير الصريح فقط؛ لا تغير سياسة ملفات الارتباط الآمنة أو أسرار الحساب. أضيفت37 حالة اختبار.
3. لم يُستبدل نطاق الخادم الافتراضي القديم تلقائيًا. يلزم التحقق من ضبط `BASIRA_PUBLIC_URL` في الاستضافة الفعلية؛ تغيير `BASIRA_IOS_WEB_ORIGIN` داخل Codemagic لا يضبط متغيرات خادم Manus.

نجحت محليًا **669 حالة Vitest في103 ملفات**، وفحص TypeScript وبناء الخادم. يثبت ذلك حدود الشيفرة فقط؛ تسجل حالة CI للالتزام الجديد في PR.

## ما يلزم لاستضافة متوافقة مع التطبيق

| البند | الحالة والمتطلب |
|---|---|
| أصل HTTPS | أصل جذري يملكه المالك، بشهادة صحيحة ومن دون مسار أساسي أو hash في إعداد التطبيق. فُحص النطاق الحالي عبر المتصفح دون تحذير شهادة؛ لم يُجرَ تدقيق مستقل للشهادة |
| مسارات التطبيق | يجب أن تعمل `/account` و`/exam-demo` و`/navigation/vision` وبقية المسارات مباشرة؛ يلزم fallback للواجهة دون تحويل API إلى HTML |
| الخادم | API وقاعدة البيانات والجلسة على الأصل المعتمد؛ تضبط `BASIRA_PUBLIC_URL` في أسرار/بيئة الخادم و`BASIRA_IOS_WEB_ORIGIN` في Codemagic بقيم متوافقة، دون نسخ أسرار إلى الواجهة |
| بوابة الاستضافة | جلسة Manus منفصلة عن جلسة Better Auth، ولا تُورّث إلى iPhone. يلزم مسار استضافة مصرح يعمل داخل التطبيق دون تجاوز بوابة أو تغيير خصوصية الإنتاج ضمنيًا |
| دخول البريد | تشترك صفحات WebKit الحالية في `WKWebsiteDataStore.default()`، ما يتيح مشاركة جلسة **نفس الأصل** بعد دخول حقيقي. يلزم اختبار كلمة مرور يدخِلها المالك، ورفض/انتهاء الجلسة والخروج، على جهاز فعلي |
| Google | لا يُسمح بإدخال مزود Google داخل WebKit الذي يستطيع التطبيق حقن السكريبت فيه. بقاء حظر النطاق الخارجي مقصود؛ فتح Safari وحده لا ينشئ جلسة WebKit |
| عودة OAuth أصلية | تتطلب تدفق متصفح نظامي وعقد عودة وخادمًا لتحويل إثبات قصير العمر يستخدم مرة واحدة ومقيدًا بالمحاولة، ثم ضبط جلسة نفس الأصل والتحقق منها. لا يوجد هذا العقد في الفرع؛ لا تُنقل ملفات الارتباط أو الرموز يدويًا ولا تُوسّع قائمة نطاقات جسر الكاميرا |
| نسخة V3 البحثية | معاينة GitHub Pages مستقلة للرؤية فقط، دون حسابات أو اختبارات أو قاعدة بيانات. مسارها الفرعي وhash لا يصلحان كبديل مباشر للأصل الجذري في التطبيق |

تمنع [سياسة Google الرسمية](https://developers.google.com/identity/protocols/oauth2/policies#use-secure-browsers) طلب OAuth داخل متصفح مضمّن يسيطر عليه المطور. توفر Apple مدخلًا لتدفق المصادقة النظامي في [AuthenticationServices](https://developer.apple.com/documentation/authenticationservices/authenticating-a-user-through-a-web-service)؛ إضافة ذلك وحده لا تنفذ عقد جلسة الخادم لتطبيق بصيرة.

قبل أي موافقة على إصدار داخلي جديد: اختبر الدخول في WebKit ثم افتح تبويب الرؤية وتحقق من بقاء الجلسة دون كشف cookie أو token، وجرّب الخروج وانتهاء الجلسة والخلفية، ثم نفذ بروتوكول iPhone14Pro الثابت. لا رفع TestFlight أو تغيير Apple أو دمج PR أو نشر على Manus الأصلي ضمن هذه الجولة.
