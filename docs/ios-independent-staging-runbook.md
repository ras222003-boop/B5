# تجهيز خادم بصيرة الكامل لبيئة اختبار مستقلة — 30 أكتوبر 2026

**الهدف:** اختبار نسخة متطابقة من واجهة React وخادم Express وMySQL الخاصة بـPR #58 على نطاق HTTPS يُدار بإذن المالك، بعيدًا عن بوابة الدخول المستقلة في Manus. **هذه تعليمات تشغيل مُعدّة ومراجَعة، وليست نشرًا فعليًا**. أي تحديث لـManus الأصلي أو رفع TestFlight يحتاج موافقة مستقلة.

## لماذا نحتاج هذه البيئة؟

النسخة الحالية على `basira-m7myneuo.manus.space` قد تُرجع `302` إلى `manus.im/app-auth` لزائر بدون Cookie، بينما `/api/readiness` يعيد `READY` و`optionalModels: DEGRADED`. وهذا يمنع تطبيق iOS من فتح جميع الخدمات العامة عبر WebKit، حتى لو نجحت اختبارات المصدر. معاينة Pages منفصلة ولا تحتوي خادم الاختبارات والحساب والخرائط. يجب **عدم** تعديل آليات OAuth أو تعطيل بوابة الأمان للتحايل على منشأ الاستضافة.

## الملفات الجديدة

- `Dockerfile`: Node 24، ينسخ الخادم والعميل والسكريبتات وكتالوج مسارات iOS ويشترط `BASIRA_SOURCE_SHA` قبل إنشاء بصمة الويب. **لا يستورد** بيانات التدريب أو الأسرار من الجهاز.
- `.dockerignore`: يستبعد ملفات البيئة والشهادات وملفات التدريب والرفع الخاصة.
- `compose.staging.yaml`: قاعدة MySQL منعزلة وخادم مستمع على `127.0.0.1:3101` فقط، وليس على الإنترنت مباشرة.
- `.github/workflows/docker-staging-build.yml`: يبني الحاوية بدون أسرار أو نشر ويتحقق من بصمة الإصدار. لا يختبر اتصال الخادم بقاعدة البيانات الحقيقية.
- `GET /api/mobile-release-info`: يعيد هوية حزمة الويب الفعلية؛ يجب أن تتطابق مع نسخة iOS.

## إعداد آمن على خادم تجارب مخوّل

1. اختر نطاقًا فرعيًا تملكه وتستطيع إعداد HTTPS عليه، **مختلفًا عن نطاق إنتاج Manus**. لا تفتح `3101` للعامة؛ استخدم وكيل HTTPS موثوقًا يدعم الكوكيز الآمنة والتحويل إلى `127.0.0.1:3101`.
2. شغّل نسخة Git **من الفرع PR #58** على الالتزام الذي تريد اختباره. احسب `git rev-parse HEAD` وضعه في `BASIRA_SOURCE_SHA`.
3. أنشئ ملف `.env.staging` محليًا على الخادم فقط (مدرج في `.gitignore`). يجب أن يحتوي `MANUS_JWT_SECRET` عشوائيًا جديدًا و`MANUS_API_KEY` أو خدمة الذكاء المصرح بها وبيانات SMTP/OAuth الاختبارية عند الحاجة. **لا تنسخ أسرار الإنتاج أو حسابات الطلاب أو قاعدة بيانات الإنتاج إلى بيئة الاختبار**.
4. خصص كلمات مرور قوية لقاعدة التجارب عبر `BASIRA_STAGE_DB_PASSWORD` و`BASIRA_STAGE_ROOT_PASSWORD`، واضبط `BASIRA_STAGE_ORIGIN` على نطاق HTTPS المختار و`BASIRA_SOURCE_SHA` على SHA الفرع. تأكد أن سلسلة `DATABASE_URL` في Compose صالحة لاسم المستخدم وكلمة المرور، واستخدم محارف كلمة مرور URL-safe أو ترميزًا صحيحًا حتى لا تنكسر سلسلة الاتصال.
5. بعد المراجعة والموافقة على نشر بيئة **اختبار فقط**، استخدم:
   
   ```bash
   docker compose --env-file .env.staging -f compose.staging.yaml config --quiet
   docker compose --env-file .env.staging -f compose.staging.yaml up --build -d
   ```

   لا يشغّل ملف Compose خادم HTTPS بنفسه؛ الوكيل الخارجي مطلوب. خادم بصيرة يستمع على المنفذ الداخلي 3000 وتُربط الخدمة محليًا على 3101.
6. تأكد أن `/api/readiness` على النطاق العام يُرجع JSON 200، و`/api/mobile-release-info` يعرض `sourceRevision` المتوقّع، وأن `/navigation/vision` و`/exam-demo` تُحمّلان HTML الأصلي دون تحويل 302.
7. شغّل من النسخة ذاتها:

   ```bash
   BASIRA_IOS_WEB_ORIGIN=https://YOUR-APPROVED-STAGING-HOST.example.org \
   node scripts/check-mobile-release.mjs
   ```

   استبدل النطاق المثال بعنوان حقيقي. **ليس هناك أي نشر جديد حتى الآن، ولا يجوز اعتباره ناجحًا من هذه الوثيقة وحدها**.
8. في Codemagic يمكن إعداد **مجموعة اختبار مستقلة** بدل تغيير `basira_unified_ios` الخاصة بالنطاق الحالي، وبعد تحقق HTTPS والجلسات والمستشعرات فقط تُطلب موافقة المالك لتشغيل TestFlight.

## شروط إضافية

- `optionalModels: DEGRADED` يعني أن النماذج الاختيارية غير مثبتة للخادم؛ **ليس تصريحًا بتوفير V3 تجاريًا**. يجب مراجعة حقوق الأوزان والحجم والمعالج وربطها بخدمة منشورة مستوفية للترخيص، لا فتح سجل الأبحاث المحلي للوصول العام.
- خدمة Google OAuth على iPhone تتطلب تدفقًا نظاميًا آمنًا وتجربة جلسة فعلية، ولا يكفي السماح بتحويل Google داخل WKWebView.
- كل وظائف LiDAR والاهتزازات وسلوك VoiceOver والألوان والدرج لا تزال بحاجة إلى iPhone 14 Pro، ولا تعني استجابة HTTPS دقة أجهزة الاستشعار أو ضمان السير.
- الإذن الحالي يسمح **بالعمل على فرع GitHub فقط**؛ لا يشمل إنشاء خدمات مدفوعة أو نشر حاوية عامة أو استبدال إنتاج Manus أو رفع Apple.

## اختبار إيقاف طارئ

إذا انكشف نطاق التجارب أو حدث خطأ أو تكلفة غير مرغوبة، أوقف التطبيق وحفظ البيانات قيد الاختبار أولًا:

```bash
docker compose --env-file .env.staging -f compose.staging.yaml stop app
```

ولا تستخدم `down -v`؛ لأنه يحذف بيانات قاعدة التجارب بلا إمكانية استرجاع تلقائي.
