# بصيرة — محرك الأمتار الموحد (المرحلة الأولى، 11 أكتوبر 2026)

## هدف هذه الدفعة

تصحيح عدم ظهور قياسات الأمتار في «رؤية بصيرة» بصورة قابلة للتحقق دون اختلاق رقم، ودون حذف أي وظائف سابقة. هذه الدفعة **لا تجعل Safari على iPhone يقرأ LiDAR**، ولا تزعم تحويل 8th Wall World Tracking/Absolute Scale إلى مسافة كرسي. تصحيح واجهة العمق ومطابقة الأطر مهم حتى نستطيع ربط الأجهزة المؤهلة بأمان لاحقًا.

## تم في الكود

1. `client/src/lib/vision/metricEngine.ts`: مزوّد عمق مترّي متحقق مع مصدر واضح: ARKit/LiDAR أو ARCore Depth أو مستشعر عمق موثوق. يتطلب `getAlignedDepth(requestedFrameTimestampMs)`، وإقرار `alignedToVideo:true`، وطابع إطار متطابق خلال 100ms، ونسبة بكسلات صالحة 60% وثقة >= 0.75. حالات المصدر: غير متاح/بانتظار القراءة/نشط/مرفوض.
2. `modelProviders.ts`: يحتفظ باسم `NativeMetricDepthProvider` القديم للتوافق، لكنه لا يقبل عمقًا بلا دليل اقتران صورة الكاميرا، وهو شرط جوهري.
3. `fusion.ts`: ربط جسم من نموذج الكائنات برقعة عمق من **الإطار نفسه** فقط؛ يتحقق من مساحة مربع الجسم والثقة و20 عينة سليمة من أصل 25، وعدم اختلاف المسافات داخل الرقعة بشدة. مسافة مركز/منتصف الرقعة تبقى **تقريبية وتجريبية** ولا تثبت أن جميع بكسلات المربع تنتمي للجسم.
4. `pipeline.ts`: فَصل استدعاء القياس عن مسار SegFormer لتقسيم المشهد؛ فشل تقسيم الأرضية لا يُوقف قراءة مستشعر العمق. تتحدث حالة المصدر في الواجهة، وتظل وصف الأمتار على طلب المستخدم، بينما تنبيهات المشي التلقائية لا تعتمد على مطابقة العمق التجريبية.
5. `Vision.tsx`: يعرض حالة توفر الأمتار ومصدرها ويشرح أن 8th Wall Absolute Scale لا يثبت المسافة إلى جسم. لا يغيّر مدى التنبيه المضبوط من المستخدم ولا بقية أزرار الرؤية.
6. اختبارات: قبول قياس محاذٍ ومتحقق من ARKit/ARCore، رفض إطار قديم أو غير محاذٍ أو غير صالح، رفض خلفيات مختلطة أو نموذج عمق نسبي، وعدم اختلاق الأمتار.

## ما لا يزال مطلوبًا لتعمل الأمتار على الهواتف

- **iPhone Safari/Chrome:** لا تتاح قراءة LiDAR من صفحة عادية. ينبغي استكمال ربط ARKit الحقيقي في التطبيق الأصلي من PR #18 واختباره على جهاز LiDAR فعلي. لا ندمج تلك PR تلقائيًا هنا لأنها تتضمن تغييرات خارج النطاق وتحتاج مراجعة الواجهات.
- **Android:** يجب بناء موصّل ARCore Depth أصلي، أو تجربة WebXR Depth على الأجهزة والمتصفحات التي تسمح بقراءة عمق مُطابق **لنفس صورة الكاميرا**. متصفح Chrome لا يكفي وحده لتأكيد الدعم. لا توجد قراءة Depth موثقة لهذا الجسر حتى الآن.
- **8th Wall:** World Tracking/Absolute Scale يقيس إزاحة/إحداثيات الهاتف في العالم، لكنه **ليس** مصفوفة عمق لكل بكسل في صورة كشف الأجسام. محرك SLAM الثنائي مقيّد بترخيص وتظل صفحة البحث معطلة افتراضيًا، ولا تدخل هذه التقنية تلقائيًا كـ `MetricDepthProvider`.
- يجب اختبار أمتار 0.5 و1 و2 و3 و5، مع الأبواب والكراسي والأسطح اللامعة، وتصوير نسب الفشل والأخطاء وP95، قبل تشغيل التحذيرات القريبة أو إعطاء توجيهات حركية تعتمد عليها.

## عقد مزود مستقبلي (للفريق/التطبيق الأصلي)

```ts
window.BasiraNativeDepth = {
  async getAlignedDepth(videoFrameTimestampMs) {
    // يتحمل التطبيق الأصلي ضمان أن نفس فيديو HTML الذي رآه النموذج
    // يقابل قيم العمق من الإطار المطابق، وليس صورة من كاميرا ثانية.
    return {
      width: 64, height: 48, values: depthInMeters,
      confidence: 0.91, source: 'ARKIT_DEPTH',
      frameTimestampMs: videoFrameTimestampMs, alignedToVideo: true,
    };
  },
};
```

هذه العينة **واجهة بيانات توضيحية فقط**، وليست مبررًا لضبط `alignedToVideo:true` دون تحقق حقيقي من عتاد الجهاز وارتباط الصورة والعمق.
