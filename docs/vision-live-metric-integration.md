## Implementation

- `VisionPipeline` continues to use one detector pass per camera frame and one non-overlapping metric inference. A metric result and its detection boxes carry the same `frameId`, source dimensions, and capture time. It never creates a `DepthReading` for AI output, so the safety fusion path cannot consume the estimate.
- The **Measure now and speak result** button is disabled until the camera pipeline is ready. It may be pressed while the metric model is loading; the request waits up to 15 seconds for the model and a frame captured *after* the press. It reports a model or frame timeout, the actual load/inference failure, or cancellation when measurement is stopped. Low light, stale inference, invalid or inconsistent depth, low confidence, and out-of-range values do not produce a number.
- `LiveVisionOverlay` draws detector boxes over the visible camera preview. Video and SVG use the same contain geometry; the native RGB canvas has already been rotated together with native depth. Object names and directions can appear on recent live frames. A number appears **only on a captured still image of the exact detector and metric input**, with matching `frameId`, capture time, and object ID. The still image is explicitly labelled as non-live and expires after six seconds. The live video never receives a numeric overlay from an earlier frame. Starting another inference or waiting for a camera frame **does not clear** the previous valid still. An accepted result replaces it; a new rejected result, confirmed low light, expiry, or stopping measurement clears it.
- The existing `AutoMeterSpeechPacer` and speech engine provide optional paced automatic announcements and an on-demand answer at information priority. Higher-priority safety announcements retain priority. The on-demand answer is also written to an accessible live status region.
- The interface shows model load and most recent inference times in milliseconds. Offscreen inference canvases are released after use. OCR, scene recognition, maps, and native-depth paths retain their existing providers.

The new code is limited to a small overlay renderer, frame geometry helper, fresh-request handling, and selection of a spoken result. They were needed because none of the reviewed samples provides Basira's frame identity, safety separation, and refusal diagnostics.

## Verification and limits

Run `corepack pnpm check`, `corepack pnpm test`, and `corepack pnpm build`. For browser checks, start Vite on `127.0.0.1:4174`, then run `node scripts/metric-depth/browser-smoke.mjs http://127.0.0.1:4174`, `node scripts/metric-depth/vision-browser-smoke.mjs http://127.0.0.1:4174`, and `node scripts/metric-depth/vision-object-browser-integration.mjs http://127.0.0.1:4174`. The integration fixture image was generated for this repository; it has no external code or model licence. The integration test uses the **real MediaPipe detector and Vision page**, but replaces only the metric provider with a constant **test-only** 1.50 m map. This controlled input verifies frame association, the visible box and Arabic label, the pinned still, and Arabic speech. It holds the second inference pending and checks that the previous still survives; it then checks replacement by a newer accepted result and removal by a rejected result, with no number over resumed live video. It does not demonstrate physical distance accuracy or that the real model accepted this object.

On 12 October 2026, TypeScript and the production build passed, as did **364 tests** (including the new pinned-still lifecycle test; the preceding run had 363). Desktop Chrome loaded the actual metric ONNX model and returned 19,200 finite pixels from a synthetic frame. The page-level Chrome test used a synthetic 640 × 480 camera stream, clicked the fresh measurement button, and returned an explicitly experimental centre-surface result of **1.93 m**; one run measured **6,589 ms model loading** and **1,015 ms inference** on this desktop host. The object integration test detected a chair at confidence **0.855**, drew its box and **≈1.50 m** label on the same pinned frame, observed multiple faster detector frames during a slower metric inference, and captured the Arabic speech utterance. Its depth map is controlled test data. Separately, `node scripts/metric-depth/object-fixture-probe.mjs` ran the **actual** FP32 ONNX model and detector on the same chair photo: the detector recognized the chair, but the metric surface was rejected as `DEPTH_INCONSISTENT` (P10 **1.52 m**, median **1.97 m**, P90 **2.66 m**). This refusal is retained; no production threshold was relaxed or distance invented. These are browser software-path checks, not physical accuracy or iPhone performance results.

The hosted Manus URL returned **HTTP 302** to `manus.im/app-auth` for unauthenticated HEAD requests to `parts.json`, `model_fp32.part-0.bin`, and `ort-wasm-simd-threaded.wasm`. A fresh in-app browser session opened the site and reached the Manus sign-in page; it had no authenticated session, so an authenticated asset request could not be made. Those redirects contain neither model bytes nor usable Content-Type and size data and do **not** establish whether a signed-in phone can load the assets. The local Vite asset check returned HTTP **200/206** for the manifest and all six model parts, and **200/200** for four WASM/module files because that development server ignores `Range` for those files. All had the expected MIME type, byte size, and non-HTML first bytes; the WASM files had the correct magic bytes. The iPhone 14 Pro Safari session could not be exercised from this Windows environment.

Physical validation remains required at **0.5, 1, 1.5, 2, and 3 m** with a tape measure, varied surfaces and lighting, and a stationary phone. Export attempts from the existing trial UI and calculate mean absolute error, P95 absolute error, and unavailable-reading rate, preserving rejections in the denominator. Until an actual iPhone run records those values, no device accuracy or Safari compatibility claim is made. AI estimates remain display and speech only; they do not trigger movement commands, collision alarms, or stair guidance.
