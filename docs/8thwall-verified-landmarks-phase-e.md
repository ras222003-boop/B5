# بصيرة × 8th Wall — المرحلة E: ربط المعالم المعتمدة وتجهيز أهداف الصور

## ما تغيّر

هذه الدفعة **تحافظ على جميع خدمات بصيرة السابقة**، وتصحح خللًا في جاهزية علامة التدريب (PR #21) مع إعداد ربط اختياري بمعالم المؤسسات الموجودة في نظام الخرائط.

### 1. لماذا يجب تصحيح العلامة؟

ملفا `client/public/ar/targets/basira-lab-marker.svg` و`basira-lab.json` كانا تجريبيين؛ بيانات image target المكتوبة يدويًا وصورة SVG **لا تثبت أنهما صالحان لمعالج تعقب الصور**. تتطلب واجهة 8th Wall ملفات تم إنشاؤها من أداة `@8thwall/image-target-cli`، بما فيها صورة luminance رمادية 480×640.

الكود الجديد يرفض تشغيل محرك 8th Wall وفتح الكاميرا في مختبر العلامات ما لم تكن ملفات CLI المعالجة موجودة، ويفحص مسار الصورة واسم الهدف وأبعاد القص والملفات المطلوبة. وضعنا رسالة مفهومة للمستخدم بدل فشل مبهم.

### 2. كيف نولّد الملفات الصحيحة على Windows؟

من جذر المشروع على الفرع الجديد نفّذ:

```powershell
pnpm install --frozen-lockfile
node scripts/prepare-8thwall-target.mjs source
npx @8thwall/image-target-cli@latest
```

في واجهة CLI اختر:
- Input image path: `client/public/ar/targets/basira-lab-entrance_source.png`
- Flat / Planar
- Default crop
- Output folder: `.basira-image-targets`
- Target name: `basira-lab-entrance`

ثم:

```powershell
node scripts/prepare-8thwall-target.mjs import
pnpm check
pnpm test
pnpm build
```

ارفع **الصور PNG وملف JSON الجديدين** داخل `client/public/ar/targets` إلى فرع المراجعة. الأدوات لا تجري تلقائيًا هنا بسبب قيود الاعتماد على معالجة صور فعلية، ولا يجوز إعلان نجاح اكتشاف العلامة قبل استكمال هذه الخطوة وفحصها من كاميرا هاتف حقيقي.

### 3. المعالم الرسمية الموجودة بالفعل في خرائط بصيرة

- `client/src/lib/ar/verifiedVenueLandmarks.ts`: وظيفة تحقق محافظة لا تقبل `imagefound` إلا إذا كانت هوية العلامة مسجلة رسميًا وتتطابق مع معرف مبنى رسمي نشط، وطابقه، وغرفة عامة موثقة، وتفاصيل المراجعة والأصول.
- لا تدّعي الدالة أن علامة مطبوعة وحدها تثبت موقع الشخص أو أن الممر آمن. ويُرفض استخدام علامة المختبر للتنقل الحقيقي.
- `/navigation/ar-lab/venues`: صفحة **قراءة فقط** للمباني العامة الموثقة والغرف المعتمدة الموجودة في خدمات `navApi` الحالية؛ يمكن تصدير **مسودة تسجيل** JSON محلية، لا تُسجل علامة ولا تعدل الخريطة أو أي بيانات.
- هذه المرحلة لا تضيف endpoint جديدًا أو صلاحية نشر معالم عامة. ينبغي مستقبلاً إنشاء سير عمل إداري مؤمّن يراجع الأصول المطبوعـة، الموقع الفعلي، مسؤول اعتماد المؤسسة وصلاحية العلامة، وإعادة اعتمادها عند تغيير الخريطة.

### 4. ما لا يُطلق حاليًا

- **لا** نفعّل محرك SLAM الثنائي أو تنبيهات الاصطدام أو إرشاد الدرج.
- **لا** تعني مصادقة القاعة أو علامة `imagefound` دقة مترية أو سلامة مسار.
- Face Effects وSky Effects في PR #22 تظل **تجارب كشف وحالات أحداث**؛ لم نثبت فلاتر الوجه ثلاثية الأبعاد أو تأثيرات السماء المرسومة على طبقة دلالية.
- World Tracking وAbsolute Scale في PR #23 هما طبقة تجريبية محجوبة بالترخيص، **غير مختبرة ميدانيًا**.
- VPS وLightship Maps وHand Tracking خارج مكونات المحرك الموزعة، فلا تُعرض على أنها موجودة.

### 5. الاختبارات وقرار الإطلاق

- اختبارات جديدة لرفض العلامات المصطنعة/غير المعالجة ولمنع ربط صورة تدريبية أو غرفة غير موثقة بمسار.
- فحوص CI: `pnpm check`، `pnpm test`، `pnpm build`، وMySQL.
- يجب تجربة Android Chrome وiPhone Safari مع QR/علامة مطبوعة، والإضاءة، وفقدان التتبع، ورفض إذن الكاميرا، وتحرير الكاميرا عند ترك الصفحة.
- نشر نسخة تجريبية بعد ترتيب PRs وبموافقة صريحة فقط. **لا دمج أو نشر تلقائي**.
