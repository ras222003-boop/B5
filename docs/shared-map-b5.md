# B5 — خريطة بصيرة المشتركة

بدأ هذا الفرع من B4 عند `8b15f7c043bf96e709a88cd9df11cdc26cc4831a`. الخريطة التشغيلية هي جداول B1 (`basira_places`, `basira_map_nodes`, `basira_map_edges`). تظل مساهمات B5 وبلاغاتها مستقلة عنها حتى مراجعة صاحب صلاحية. لم تُنشأ خريطة موازية للملاحة.

## دورة المساهمة

1. يوافق المستخدم صراحة على إرسال معلومة **عامة**. ترسل B2 قراءة OCR والنوع والثقة فقط، مع تقدير الموضع والطابق من B3؛ لا ترسل صورة. يمكن للمستخدم إدخال مكان أو تصحيح يدويًا. ويمكن للمراجع استيراد اقتراح B3 المقبول إلى سجل B5 دون إعادة اعتماد `PENDING` تلقائيًا.
2. يتحقق الخادم من المبنى والطابق والعنصر المستهدف، ومن حد أدنى لثقة التموضع وتوافق الدليل. يخزن معلومات العنصر والدليل المحدود وحالة `PENDING`. لا يسمح مخطط الطلب بتمرير إطار الكاميرا أو سجل المسار أو معرّف `SavedPlace`.
3. يطبع `SharedPlaceResolver` أسماء الغرف وأرقامها، ويطابق العناصر المتقاربة أو المرتبطة بالعقدة/الحافة نفسها. يعيد B5 استخدام `MapDeduplicationService` من B3 بعد نقله إلى وحدة مشتركة دون تغيير عقده، ويضيف مطابقة أسماء الغرف وهندسة الممر. يجمع `ContributionCorroborationService` الاقتراحات المتطابقة تحت `root_id` واحد. يشمل ذلك ١٢١ و«قاعة 121» و`Room 121`، والممر ذا الطرفين المعكوسين. يبقى اختلاف الطابق/الغرفة أو الإحداثيات المرشح لتغيير المكان مستقلًا.
4. يحسب `SharedMapConfidenceEngine` الثقة من الفاعلين المستقلين، والجلسات والأجهزة، وثقة التموضع وOCR والمرجع البصري، وتوافق الطابق والمكان، وحداثة الملاحظة والتعارضات. يحتسب أفضل دليل واحد لكل فاعل. يشترط الإعداد الافتراضي 3 فاعلين، وجلستين وجهازين مستقلين، وثقة ≥ 0.75، ومتوسط تموضع ≥ 0.55، وغياب التعارض. تتطلب التغييرات الأعلى أثرًا فترة ملاحظة 24 ساعة. القيم في `DEFAULT_SHARED_MAP_POLICY`.
5. تعرض الواجهة `PENDING` و`CORROBORATING` و`COMMUNITY_VERIFIED` كمرشحات بعبارات نوعية. لا تمنح مساهمات المستخدمين `OFFICIAL` تلقائيًا. يحول `MapPromotionService` قرار mapper/admin المعتمد إلى كتابة مضبوطة في B1، داخل معاملة واحدة مع رفع إصدار المبنى وحفظ سجل التغيير.

## التعارض والتغيير

إذا اختلفت غرفة العيادة الرسمية 305 عن اقتراح 312، يسجل `MapConflict` و`PlaceChangeCandidate` مع نسخة الحالة السابقة والمقترحة والدليل وعدد التأكيدات. لا يُعدل المكان قبل مراجعة المراجع وحل التعارض صراحة. `STALE` يعني أن الدليل مضى عليه أكثر من سنة دون تأكيد حديث؛ لا يحذفه النظام. البلاغات المؤقتة مثل كرسي أو ازدحام محفوظة بنوع `TEMPORARY` وتصل إلى قائمة المراجعة، ولا تُنشئ جدارًا أو إغلاقًا دائمًا تلقائيًا. تعطى تقارير الدرج غير المسجل والإغلاق والإتاحة أولوية عرض أعلى.

## الخصوصية ومقاومة الإساءة

- `SavedPlace` خاص ولا يرسل تلقائيًا. واجهة «أماكني» تفتح نموذج مساهمة منفصلًا بموافقة جديدة، دون نسخ بيانات المكان الخاص. تُرفض بعض تسميات المنزل والسيارة الصريحة. يحتاج المراجع إلى التحقق من أن المكان عام بالفعل؛ لا تستطيع تصفية الأسماء الآلية حسم ذلك.
- لا تُعرض هوية المساهم أو الجلسة أو الجهاز للعامة. تستخدم البصمات SHA-256 لحقائق العنصر العامة فقط. تُجزّأ مفاتيح الفاعل والجلسة والجهاز بـ HMAC نطاقه المبنى لحساب الاستقلالية، ولا تُعرض في API العام. تخزن الواجهة مفتاح جلسة مؤقتًا ومفتاح جهاز عشوائيًا لمقاومة تكرار التصويت؛ لا يخزن دليل المسار.
- حدود إرسال المساهمات والتأكيدات والبلاغات قابلة للضبط. مفاتيح idempotency فريدة في قاعدة البيانات، والتأكيد فريد لكل فاعل وجذر. طابور العمل دون اتصال في `sessionStorage` يحتفظ بالطلب المصرح به فقط، ويرسل عند عودة الاتصال؛ يستند الخادم إلى المفتاح الفريد عند إعادة المحاولة.

## الإصدارات والملاحة

تبدأ كل خريطة B1 موجودة عند الإصدار 1 عند أول تغيير مُتتبع في B5، ثم يزيد `MapVersion` داخل معاملة الاعتماد. قبول B3 الذي يكتب مكانًا أو عقدة أو حافة جديدة في B1 يسجل التغيير ويرفع الإصدار أيضًا؛ إذا لم يغيّر شيئًا فلا يزيده. يسجل `basira_map_change_log` الكيان السابق واللاحق ونوع المصدر ووقت المراجعة. تعرض API العامة بيانات التغيير دون هوية المساهم أو صور أو مسارات. يتيح التراجع لـ admin فقط عكس تغييرات إصدار محدد بترتيب معكوس، بعد مقارنة حالته الحالية بلقطة ما بعد التغيير؛ ينشئ التراجع إصدارًا جديدًا، ويرفض الكتابة فوق تعديل لاحق للكيان نفسه.

`SharedMapSyncService` يستعلم عن رقم الإصدار ثم يجلب رسم B1 المعتمد فقط عند تغيره. لا تنتظر الملاحة قائمة `PENDING`. يؤجل B4 تغيير مكان أو ممر عاديًا إلى نقطة تثبيت معروفة أو نهاية الجلسة؛ يطبق إغلاق الحافة أو التراجع المؤثر في الحافة بسرعة مع إعادة حساب المسار. عند انقطاع الشبكة تستمر الخريطة المخزنة مع تنبيه أن بيانات الإغلاق قديمة. يرتبط البحث والتوجيه بأماكن وعقد B1؛ إذا كان المكان الجديد لا يتصل بعقدة قابلة للوصول، يظهر في البحث لكن لا يبدأ B4 مسارًا حتى يعتمد المراجع اتصالًا مناسبًا في الخريطة.

## API والصلاحيات

كل المسارات تحت `/api/navigation/shared-map`:

| المسار | الغرض | الصلاحية |
| --- | --- | --- |
| `POST /contributions` | إرسال معلومة عامة بموافقة ومفتاح idempotency | مستخدم مسجل |
| `GET /buildings/:id/candidates` | المرشحات العامة المحدودة دون هوية | عام |
| `POST /contributions/:id/confirm` | تأكيد مستقل واحد | مستخدم مسجل |
| `POST /contributions/:id/conflicts` | الإبلاغ عن تعارض | مستخدم مسجل |
| `POST /issues` | بلاغ مؤقت/مستمر | مستخدم مسجل |
| `GET /contributions/:id` | تفاصيل مساهمته أو تفاصيل للمراجع | المساهم أو مراجع |
| `GET /buildings/:id/contributions`, `GET /buildings/:id/issues` | طابور المراجعة | mapper/admin |
| `POST /contributions/:id/review`, `POST /issues/:id/review` | اعتماد/رفض/طلب أدلة أو معالجة بلاغ | mapper/admin |
| `POST /map-suggestions/:id/import` | نقل مصدر B3 المقبول إلى سجل المساهمات | mapper/admin |
| `GET /buildings/:id/version`, `GET /buildings/:id/sync` | رقم النسخة وتغيرات معتمدة | عام |
| `GET /buildings/:id/history`, `POST /buildings/:id/rollback` | التاريخ والتراجع | admin |

الصلاحية `ORGANIZATION` موجودة في العقد فقط للتكامل المستقبلي؛ استقبال بيانات المؤسسة غير مفعل في B5. لا يبدأ هذا العمل B6.

## التخزين والاختبار

الهجرة الإضافية `server/migrations/0005_shared_map.sql` تنشئ المساهمات، التأكيدات، التعارضات، مرشحات انتقال الأماكن، البلاغات، إصدارات الخرائط، وسجل التغيرات. لا تعدل هجرات B1–B4. الاختبارات تغطي تطابق 121، منع تكرار الفاعل، عتبات الاستقلالية والزمن، التعارض والانتقال، عزل المكان الخاص، الصلاحيات، إدراج Place/MapNode في B1، رفع الإصدار والتراجع، الطابور دون اتصال، وفصل البلاغ المؤقت عن المستمر. لا يوجد اختبار E2E أو قياس ميداني لسلامة الملاحة في هذه المحطة.
