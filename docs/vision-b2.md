# B2 — Basira Vision

## Runtime

`/navigation/vision` starts an exploration-only session after a user gesture. `CameraService` requests the camera at that point, prefers the rear camera, and stops every track when vision stops, the page unmounts or the tab becomes hidden. Analysis is bounded to two object frames per second and one OCR frame per eight seconds. It never queues camera frames; the temporary OCR blob is released after recognition.

The pipeline runs COCO object detection at up to 2 Hz, semantic segmentation at 0.2–0.55 Hz depending on hardware tier, native depth when a camera-aligned bridge exists, optional relative monocular depth on high-tier browsers at most once per 6 seconds, and OCR once per 8 seconds. `VisionFusionEngine` combines these into one ordered risk and walkable-area result. Segmentation/depth run without queuing frames; COCO remains active while these slower tasks work. B1's `/api/navigation/search` is used for matching; no second map is created. A sign may be associated with the nearest aligned door, but the match remains tentative. Unmatched navigation text becomes a `PlaceCandidate` with `PENDING` review status in the current page's private memory. It is not published or persisted. B3/B5 can attach a reviewed repository to the typed contract later.

## Models and assets

- Local object detection: Google MediaPipe Tasks Vision 1.0.1 and EfficientDet-Lite0 int8 (COCO, 320×320 model input). The model is sourced from [Google's published model](https://storage.googleapis.com/mediapipe-models/object_detector/efficientdet_lite0/int8/latest/efficientdet_lite0.tflite); SHA-256 `0720BF247BD76E6594EA28FA9C6F7C5242BE774818997DBBEFFC4DA460C723BB`.
- Local scene segmentation: [Xenova's quantized SegFormer-B0 ADE20K model](https://huggingface.co/Xenova/segformer-b0-finetuned-ade-512-512) through Transformers.js 3.7.6 and ONNX Runtime Web. Its 150 semantic labels include stairs/stairway/step, door, column, wall, floor, road, sidewalk, path, fence and box. Quantized ONNX SHA-256 `9A98D6DAF3D926869AB8CC4C2ED7374A2BC23B889BB7CA3B0915D15E3C4756BB`.
- Optional local relative depth: [Depth Anything V2 Small](https://huggingface.co/onnx-community/depth-anything-v2-small), quantized ONNX SHA-256 `FCF51F1B230362B28690BB9D1809BF0431F29CAD20534E3F589BD7285547F20D`. Its output is normalized **relative** structure, never metres. It only runs on the high hardware tier, and is skipped if a native metric bridge is available.
- Local OCR: Tesseract.js 6.0.1 with local `ara`, `eng` and `chi_sim` trained-data packages. The worker, WASM runtime and language data are served under `/vision/tesseract`.
- All image processing stays in the browser. No frame is sent to the Basira server or a cloud vision service. Only navigation-relevant OCR text is sent to B1 search for place matching. If B1 is offline, the text remains a local pending candidate and the UI says matching could not be checked.
- Public assets under `client/public/vision` total about 142 MB before HTTP compression. They are copied into the production build. A fresh offline page load is not supported because this project has no service worker; an already loaded session continues inference when all relevant model, runtime and OCR files have loaded. Initial model loading can take noticeably longer on a slow connection or phone.

## Safety limits

EfficientDet-Lite0's COCO labels support persons, chairs, dining tables, bicycles, vehicles and some road signs. SegFormer now contributes **real semantic regions** for stairs, doors, walls, columns, barriers, floor and bulky non-COCO objects. A connected-component pass gives approximate boxes and directions. Semantic masks provide no calibrated detection scores; the exposed score is a conservative region-quality heuristic. The model has not been validated on Basira's target environments, so this is not a reliable safety detector. Entrances/exits are inferred only from recognized signs and are not asserted from door appearance alone.

SegFormer identifies a stair **region** but cannot distinguish up from down from its ADE20K class. It emits `STAIRS_UNCERTAIN`, with a cautious warning. No code path labels stairs `UP` or `DOWN` from RGB alone. `DropOffHazardDetector` combines a terminating ground mask with an abrupt depth change and can emit only `DROP_OFF_UNCERTAIN`. This is a possible level change, not a confirmed hole or curb. It can miss hazards and produce false alerts; a single camera view is insufficient to establish a reliable drop-off. No model here was trained specifically for pits or curb edges.

`SemanticWalkableAreaProvider` samples floor/road/sidewalk/path coverage across left, centre and right sectors and considers detected obstacles. `CLEAR` means only that the currently visible semantic mask has substantial apparent free area; the user-facing text never calls it safe. `BLOCKED` and `UNKNOWN` are likewise approximate. This does not supply route guidance or permission to proceed.

The web app has no portable ARKit/ARCore/LiDAR metric depth stream. `NativeMetricDepthProvider` accepts a validated camera-aligned metric map from `window.BasiraNativeDepth` when a native wrapper supplies it; no iOS/Android bridge is implemented in this web repository. On high-tier browsers, Depth Anything provides only relative depth. No distance in metres is inferred from it or from bounding-box size, and the safety engine does not escalate to `CRITICAL` without reliable measured metric depth. The screen warns that Basira Vision is exploratory assistance, not a sole mobility aid.

Capability detection checks camera, WebGL, WebGPU, a native depth bridge, device memory and CPU cores. It selects a 1.8/3/5 second segmentation cadence and enables monocular depth only on high-tier devices; native depth has priority. WASM is currently used for broad browser compatibility even when WebGPU exists. Battery awareness halves the COCO analysis rate on supported devices at 20% battery or below. Browsers do not expose a portable thermal sensor, so no thermal adaptation is implemented. Telemetry is local, aggregate session logging only: frame count, detection count and average inference time, without frames, recognized text or precise location. The configured cadences are not measured mobile frame rates; phone latency and thermal behavior remain unverified.

## Verification

Unit tests cover risk classification, stair/drop-off priority, the critical-depth gate, direction buckets, alert cooldown/escalation, semantic label mapping, walkable sectors, fusion, B1 room matching, pending candidates and camera permission error mapping. Both ONNX models were loaded and inferred against a synthetic image in a local Node CPU smoke check. Browser camera, WASM inference, model accuracy, latency and screen reader flow still require validation on target phones before treating B2 as a field-ready safety feature. No B3/B4 navigation, voice commands or route calculation is implemented.
