# تقرير فرع الاقتراب الذكي والاهتزازات المتصاعدة

التاريخ: 27 أكتوبر 2026. [فرع التطوير `codex/basira-adaptive-approach`](https://github.com/ras222003-boop/B5/tree/codex/basira-adaptive-approach) في مستودع B5. بدأ من حالة `codex/basira-colour-quality-v3` الحالية دون دمج الفروع المتراكبة. رُفع الفرع للمراجعة فقط؛ لم يُدمج ولم يُنشر إصدار معاينة أو إنتاج.

## ما نُفذ

- أضيف محرك `SmartApproachRiskEngine` فوق متتبع الهوية والتدفق البصري المعوض الموجودين. يقيم موضع الجسم، انتقاله، أدلة التمدد، المسار المحتمل ضمن الصورة، عمر الإطار وجودة التتبع، ويحسب TTC تقريبيًا فقط عند اتفاق إشارات الحركة. مستويات القرار متدرجة مع تثبيت قبل الرفع، وتهدئة وعدم تكرار على الإطار نفسه.
- يتيح المسار النسبي تنبيهًا مبنيًا على الحركة المرئية المؤهلة. المسار المتري يطلب عمقًا موثوقًا متزامنًا مع RGB من الجسر الأصلي الموجود. لا تدخل أمتار النموذج الأحادي غير المعاير أو قراءة `approximateDistance` القديمة في قرار الاقتراب.
- كُبح تحذير الأجسام المعتادة المبني على الكشف وحده في صفحة الرؤية، وبقي وصفها منفصلًا. بقيت ملاحظات الدرج والحافة المتخصصة ضمن مسار السلامة الموجود. تظهر «تقدير غير متاح» عندما لا تكفي الأدلة، من دون وصف الطريق بأنه آمن.
- أضيفت إعدادات محلية لقناتي الصوت والاهتزاز، الحساسية، طريقة التنبيه، حدود المسافات المترية، نمط النبضات وشدتها إن دعم الجهاز ذلك، مع اختبار وإعادة تعيين. الإعداد الافتراضي صامت لتنبيهات الاقتراب. أُضيفت نبضات قصيرة متباعدة تتسارع مع مستوى الخطر وتتوقف عند زوال الدليل أو تقادم الإطار.
- أضيف جسر Core Haptics إلى تطبيق iPhone القائم، وجسر Android VibrationEffect إلى تطبيق ARCore القائم. كلاهما يتحقق من الأصل والصفحة والجلسة وعمر الإطار، ويحد مدة النبضة ومعدلها، ويوقفها عند مغادرة الصفحة أو توقف الكاميرا.
- أضيفت أداة حساب لمقارنة التنبيهات بوسم بشري مستقل عندما تتوفر بيانات ميدانية، مع بروتوكول السيناريوهات والقياسات المطلوبة في [سجل التحقق](approach-adaptive-alerts.md).

## التحقق المنجز

- `npm run check`: نجح.
- `npm run build`: نجح.
- اختبارات `client/src/lib/vision`: نجحت 222/222 في تشغيل المجلد قبل اختبار دمج إضافي، ونجح اختبار الدمج أيضًا. نجح اختبار أداة حساب المقاييس 2/2.
- `npm run test:approach-browser` في Chrome حقيقي مع صورة كرسي على بث كاميرا اصطناعي: نجح. تحقق من حفظ الإعدادات واستعادتها، حالة عدم دعم الاهتزاز، إتاحة لوحة الإعدادات دون مخالفات Axe جسيمة/حرجة، إظهار جسم وإيقاف الجلسة، ومن عدم وجود أخطاء JavaScript. حفظ التقرير في `.basira-evidence/approach-browser-smoke.json` محليًا.
- التشغيل الكامل `npm test` مع السماح لاتصال الاختبارات المحلي `127.0.0.1`: نجح 547/547 اختبارًا في 97 ملفًا. التشغيل الأول داخل عزل الشبكة فشل في اختبارات خادم تتطلب localhost، ثم اجتازت المجموعة نفسها جميع الاختبارات عند إتاحة ذلك الاتصال.

## ما ينتظر التحقق

- لم يتوفر هنا macOS/Xcode والتوقيع لبناء iOS أو جهاز iPhone حقيقي لاختبار Core Haptics وLiDAR. ملف `codemagic.yaml` يجهز بناء TestFlight داخليًا بعد ضبط تكامل Apple و`BASIRA_VISION_URL` على موقع تجريبي منشور؛ لم تتوفر صلاحية التوقيع أو ذلك الرابط لتشغيله هنا. لم يتوفر Android SDK/JDK 17 وتجربة جهاز Android مدعوم للتحقق من ARCore والاهتزاز الفعلي. لم يُجهز TestFlight أو APK تجريبي، ولم يُختبر صوت قارئ الشاشة على الهاتف.
- لم تتوفر مقاطع موسومة مستقلة ومرخصة أو قياسات مرجعية لمسافة الجسم ولا بيانات استهلاك البطارية والذاكرة على هاتف فعلي. لذلك لا توجد نسب إنذار خاطئ أو فوت خطر أو خطأ مسافة ميدانية مثبتة، ولم يُدرَّب نموذج أو تُعلن نتيجة معايرة.
- المحرك يمتنع عن تقييم اقتراب كاميرا تتحرك نحو جسم ثابت عندما يبدو تمدد الخلفية عامًا؛ يلزم مستقبلًا دليل حركة كاميرا موثوق وقياس عمق متزامن قبل السماح بهذه الحالة. العائق الصغير أو المنخفض الذي لا يكشفه نموذج الأجسام لا يحصل على تقييم اقتراب منه.
- قورنت رؤوس PR #28 و#37 و#53 عبر Git refs دون دمجها: رأس #37 (`f4ca091`) ورأس #53 (`9706863`) سلفان للفرع؛ رأس #28 (`0e032e6`) ليس سلفًا، لكن جسر ARKit الموجود محليًا أُعيد استخدامه. لا تحدد Git refs وحدها حالة إغلاق الطلبات. لم يتوفر رابط معاينة منشورة لأن النشر يحتاج موافقة وبيئة استضافة.
