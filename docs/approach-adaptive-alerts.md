# الاقتراب الذكي والتنبيهات المتصاعدة — سجل التحقق

هذه إضافة تجريبية إلى صفحة «رؤية بصيرة». لا تعني قراءة «لا دليل اقتراب» أن المسار آمن، ولا تصلح الأداة وحدها لتوجيه المشي أو منع الاصطدام. يبقى وصف الجسم منفصلًا عن إنذار الاقتراب.

## مصادر الأدلة وحدودها

- يستخدم التتبع الحالي من PR #37 هوية الجسم المستقرة، والتغير الزمني لمساحة الصندوق، والتدفق البصري بعد تعويض حركة الخلفية. لا يصدر إنذار من كبر الصندوق أو تمركزه أو درجة النموذج وحدها.
- تقاس المسافة النسبية بعبارات ومستويات لا بأمتار. تقدير TTC تقريبي ولا يعرض إلا عندما تتفق إشارات التمدد المقاسة عبر إطارات حديثة ومتتابعة؛ لا يمثل احتمال تصادم.
- المسافة المترية مرخصة لمحرك التنبيه فقط عندما يأتي عمق ARKit/LiDAR أو ARCore أو مستشعر موثوق من الصورة نفسها، مع تحقق المحاذاة والتغطية والجودة. عمق الرؤية الأحادية ونموذج `MONOCULAR_METRIC` يبقيان للعرض التجريبي المنفصل ولا يقدمان أمتارًا لتحذير.
- اتجاه الكاميرا لا يثبت اتجاه مشي المستخدم. نطاق منتصف الصورة قرينة محدودة للمسار المحتمل؛ المرور الجانبي وحركة الكاميرا السريعة يخفضان الثقة أو يلغيان التقييم. أي فقد للتتبع، انخفاض للإضاءة، تأخر للإطار أو توقف للكاميرا يلغي حالة الإنذار والنبضات الجارية.
- الحساسية وحدود المستخدم تغيران **سياسة الإعلان** ضمن الأدلة المتاحة، ولا تغيران قراءة الحساس أو ثقة العمق.

## تجربة التقييم الميداني المطلوبة

صُنع فرع التطوير واختبارات آلية بمشاهد صناعية. **لا توجد في المستودع عند كتابة هذه الوثيقة مقاطع مراجعة بشرية مستقلة لهذا المحرك، ولا قياسات بطارية أو ذاكرة لهاتف فعلي. لم تحسب نسبة إنذارات ميدانية أو تُثبت دقة أو فاعلية.** يلزم جمع بيانات مناسبة ومرخصة قبل المعايرة أو التدريب. تُثبت نسخة النموذج والمعاملات وتُفصل بيانات التطوير والاختبار على مستوى الأشخاص والأماكن والمقاطع، كما في [بروتوكول التقييم العام](basira-field-evaluation.md).

تُصوَّر وتوسم على جهاز فعلي المقاطع التالية، بما فيها لحظة بدء الخطر ومستواه ونهاية الدليل، بواسطة موسمين مستقلين ثم تحكيم اختلافهما:

| السيناريو | ما يجب تسجيله والتحقق منه |
| --- | --- |
| جسم بعيد ثابت؛ جسم قريب ثابت | غياب إنذار اقتراب آلي من القرب الظاهري وحده |
| جسم يقترب تدريجيًا؛ جسم يبتعد | توقيت مستوى الخطر، والتراجع عند زوال الدليل |
| شخص يمر جانبًا؛ أجسام متعددة | اختيار الجسم المرتبط بالمسار، وعدم إطلاق نبضات لكل جسم |
| كاميرا تتقدم نحو ثابت؛ حركة كاميرا سريعة أو دوران أو تكبير | أثر تعويض الحركة، وفشل التقييم بأمان عند عدم كفاية الأدلة |
| إضاءة ضعيفة؛ فقد التتبع؛ توقف الكاميرا | «تقدير غير متاح»، وعدم استخدام إطار قديم أو إبقاء نبضات |
| عائق منخفض أو جسم صغير | معدل الفائت، مع التصريح بالفئات التي لم يدعمها النموذج |

يسجل وقت التقاط الإطار، الاستدلال، القرار، بداية الصوت **المسموعة** وبداية الاهتزاز **الفعلي**؛ وقت استدعاء API وحده لا يثبت وصول الصوت أو الاهتزاز. تسجل أيضًا قراءات مسافة مرجعية مستقلة عند وجود حساس متري، وبيانات البطارية والذاكرة من أدوات الجهاز خلال جلسات متكافئة. يقارن الإصدار السابق والمرشح على المقاطع والأجهزة نفسها دون تعديل عتبات الاختبار بعد الاطلاع على النتائج. يلزم اختبار iPhone مزود بالمستشعر المطلوب وAndroid مدعوم، مع VoiceOver وTalkBack؛ المحاكي لا يثبت LiDAR أو اهتزاز الجهاز.

أداة الحساب المنفصلة:

```sh
node --test scripts/approach-evaluation.test.mjs
node scripts/approach-evaluation.mjs labelled-run.json report.json
```

لفحص الواجهة في Chrome محليًا بعد تشغيل معاينة Vite على المنفذ 4186:

```sh
npm run test:approach-browser
```

يفحص هذا الاختبار الإعدادات والإتاحة وكاميرا اصطناعية بصورة كرسي ثابت؛ لا يمثل اقترابًا حقيقيًا أو اختبار اهتزاز هاتف. يحفظ نتائجه في `.basira-evidence/approach-browser-smoke.json`.

الإدخال JSON يحتوي `schemaVersion:1` و`dataset:{id,split,labelStatus,annotatorIds}` و`clips`. لكل مقطع: `id`, `scenario`, `durationMs`, و`truth:[{id,onsetMs,offsetMs,level}]`, و`alerts:[{atMs,level}]`, و`haptics:[{actualStartMs,durationMs}]`, و`levels:[{atMs,level}]`. المستويات هي `NONE`, `CAUTION`, `HIGH`, `CRITICAL`. الحقول الاختيارية `metricSamples:[{referenceMeters,estimatedMeters,source}]`, و`inferenceMs`, و`memoryMb`, و`battery:{startPercent,endPercent}`. يتطلب تقسيم `test` أو `validation` `labelStatus:"INDEPENDENT_ADJUDICATED"` ومعرفين مختلفين للموسمين على الأقل. تقسيم `synthetic` مخصص لفحص الحساب فقط.

التقرير يحسب حصة الإنذارات الكاذبة، معدلها لكل ساعة، حصة أحداث الخطر الفائتة، متوسط وP95 تأخر أول إنذار وأول نبضة، عدد تبدلات المستوى لكل دقيقة، MAE لقراءات العمق الموثوق، P95 الاستدلال، ذروة الذاكرة وانخفاض البطارية. القيم غير المقاسة تبقى `null`. هذه مقاييس ضمن المقاطع الموسومة فقط؛ لا تستنتج منها سلامة تنقل الأشخاص المكفوفين.

يحتاج تجميع iPhone إلى macOS وXcode والتوقيع، ويحتاج إثبات Core Haptics وLiDAR إلى iPhone حقيقي. يحتاج تجميع Android إلى Android SDK/JDK وقياس الاهتزاز وARCore على جهاز فعلي. لا يُنشر هذا الفرع أو يُدمج قبل نتائج المتصفح والهاتف والتقييم المستقل والموافقة.
