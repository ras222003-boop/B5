# بصيرة — E7: القياس المستقل والتقييم الميداني

تاريخ الإعداد: 13 أكتوبر 2026. **الحالة: بروتوكول مقترح وأداة حساب مقاييس؛ لم يراجعه أو يوقعه اختصاصي توجه وحركة، ولم تُنفّذ تجربة مشاركين ضمن هذا التقرير.** نجاح الحسابات أو اختبارات المتصفح لا يستوفي اختبارات الهاتف والميدان.

## تثبيت البيانات قبل الضبط

1. تُسجل نسخة النموذج وSHA-256 للأوزان، commit التطبيق، عتبة الثقة، NMS، دقة المدخل، مصدر المعالجة ونسخة المتصفح. تُحفظ بيانات baseline وcandidate منفصلة.
2. تجمع صور وفيديوهات ذات حقوق استخدام وموافقة مناسبة. لا تُجمع صور المارة أو الوجوه للتدريب افتراضيًا. تُحدد سياسة حذف واحتفاظ، وتُطمس بيانات التعريف في التقارير.
3. تقسيم على مستوى **المكان والرحلة والفيديو والمستخدم** إلى تدريب/ضبط/اختبار. لا تتوزع إطارات متجاورة من الفيديو نفسه بين الضبط والاختبار. يُقفل manifest وhash قبل تغيير عتبات المرشح.
4. يوسم شخصان مستقلان الفئات والصناديق وقناع الأرضية وأحداث الحافة/الدرج والظلال. تُراجع الخلافات، ويُثبت دليل تعريف الفئة. لا يُعامل عدم وجود وسم على أنه غياب جسم إلا بعد مراجعة الإطار كله.
5. تشمل السالبات الصعبة الظلال والرخام اللامع والمبلل وتغير اللون والنقوش وشقوقًا سطحية. وتشمل الموجبات كرسيًا/سيارة/شخصًا/حقيبة وحجبًا وأجسامًا صغيرة ودرجًا وبلاطًا مرتفعًا وأسلاكًا؛ لا تحذف الفئات غير المدعومة من تقرير الفجوات.
6. اقتراح أولي للعينة، يحتاج إقرارًا قبل الجمع: 30 مقطعًا مستقلاً على الأقل لكل عائلة سيناريو، و200 ظهور موسوم على الأقل لكل فئة حرجة، مع سالبات من 3 أماكن مستقلة أو أكثر. ليس ذلك تحليل قدرة إحصائية أو عددًا كافيًا لإثبات السلامة. يجب إظهار عدد الأحداث المستقلة لا عدد الإطارات المترابطة وحده.

## المقاييس وتعريفاتها

| المقياس | التعريف والتقرير |
| --- | --- |
| Precision/Recall | لكل فئة عند score ثابت وIoU=0.50؛ ذكر TP/FP/FN والعينة؛ `null` عندما لا يوجد مقام |
| AP50:95 | مطابقة صناديق واحد لواحد مرتبة بالثقة، IoU من .50 إلى .95 بخطوة .05، واستيفاء precision على 101 مستوى recall |
| الأجسام الصغيرة | شريحة معلنة مسبقًا حسب مساحة الصندوق بالبكسل الأصلي؛ لا تخلط حد COCO بالبكسل مع مساحة normalized |
| IoU/Dice | لكل فئة قناع وعلى مستوى مجموعة الاختبار؛ استثناء ignore بناء على الحقيقة الأرضية فقط؛ ذكر حجم القناع وطريقة التحجيم |
| الفائت والإنذار الكاذب | أحداث مستقلة لكل فئة خطر/مدة مراقبة بالدقائق؛ عدم عد إنذار متكرر للجسم ذاته أحداثًا مستقلة |
| التتبع | تبديلات هوية/دقيقة ومدة الفقد وIDF1 أو HOTA بأداة معيارية؛ معرفات حقيقة أرضية ومسارات مستقلة مطلوبة |
| مؤشرات الاقتراب | أحداث اقتراب/ابتعاد/دوران/zoom/مرور جانبي؛ confusion matrix وfalse warnings/minute؛ ليس «احتمال اصطدام» |
| التأخير | p50/p95 للاستدلال وحده، وللالتقاط حتى أول صوت مسموع، ولعمر الإطار عند نشره؛ فصل تحميل النموذج والإحماء |
| FPS الفعلي | عدد إطارات مختلفة **اكتمل تحليلها** ÷ مدة المراقبة؛ لا تستخدم معدل طلبات scheduler أو إعادة استخدام نتيجة |
| الذاكرة والبطارية | قياس أدوات الجهاز/النظام إن أتاحتها؛ baseline متكافئ للسطوع والشبكة والحرارة ومدة الجلسة؛ `not measured` عند الغياب |

المرجع الحسابي لـCOCO هو [cocoeval.py الرسمي](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py). أداة المستودع أدناه تطبق التعريف المحدود المعلن، **ولا تعادل تقييم COCO الرسمي**: لا تدعم crowd/ignore في الصناديق أو area ranges أو قائمة maxDets القياسية. عند نشر نتيجة باسم COCO يُستخدم pycocotools مع التنسيق الأصلي، لا تُعاد تسمية مخرج الأداة.

تُعرض فواصل ثقة 95% للنتائج على مستوى المقاطع المستقلة أو bootstrap بالمقطع، لا بإعادة أخذ إطارات مترابطة وكأنها عينات مستقلة. تُقارن النسختان على المشاهد والأجهزة نفسها؛ لا يُعلن تحسن لمجرد اختلاف صورة الإدخال أو درجة الحرارة.

## أداة التقييم القابلة للتشغيل

```sh
node --test scripts/perception-evaluation.test.mjs
node scripts/perception-evaluation.mjs /path/to/annotated-run.json /path/to/report.json
```

أداة `scripts/perception-evaluation.mjs` **لا تشغل النموذج ولا تصنع بيانات اختبار**. تستقبل annotations مع predictions من تشغيل حقيقي، وتحسب المقاييس. الاختبارات المرافقة صناعية لاختبار الحسابات فقط. كل النتائج بين 0 و1، وليست نقاطًا مئوية. الأمثلة التالية توضح شكل البيانات، ولا تُعد عينة ميدانية:

```json
{
  "schemaVersion": 1,
  "dataset": { "id": "schema-example", "split": "synthetic", "annotationRevision": "1" },
  "run": { "model": "none-example-only", "device": "none", "browser": "none" },
  "options": { "scoreThreshold": 0.45, "maxDetectionsPerFramePerClass": 100 },
  "samples": [{
    "id": "frame-1",
    "groundTruth": [{ "class": "chair", "box": { "x": 0.1, "y": 0.1, "width": 0.2, "height": 0.2 } }],
    "predictions": [{ "class": "chair", "score": 0.9, "box": { "x": 0.1, "y": 0.1, "width": 0.2, "height": 0.2 } }],
    "mask": { "width": 2, "height": 2, "groundTruth": [1, 1, 0, 255], "prediction": [1, 0, 0, 1], "ignoreLabel": 255 }
  }]
}
```

- `split` أحد `test` أو `validation` أو `synthetic`. لا تتحقق الأداة من استقلال البيانات أو موافقتها؛ المسؤول عن الدراسة يتحقق منها. يُبقي التقرير بيانات المصدر واضحة.
- الصناديق `xywh` نسبية ضمن [0,1] بإحداثيات **الصورة الأصلية نفسها** في الحقيقة والتوقع. تُعكس عملية letterboxing قبل التصدير. `class` اسم موحد ثابت، و`score` بين 0 و1.
- كل إطار يحتاج صراحة إلى `groundTruth` و`predictions` حتى إن كانتا فارغتين. تُرفض معرفات الإطارات المكررة وNaN والأبعاد غير الصالحة ووسوم crowd/ignore للصناديق.
- P/R يستخدمان عتبة التشغيل؛ AP يستخدم كل الدرجات **المصدرة**. يلزم تصدير توقعات منخفضة الثقة أيضًا للتقييم؛ لا تستطيع الأداة استرجاع ما حذفه provider قبل التصدير. تثبت عتبة التصدير مع النتائج.
- يُطبق الحد 100 لكل فئة/إطار افتراضيًا؛ ترتيب الثقات المتساوية مستقر وفق ترتيب الإدخال. الفئة ذات FP دون أي حقيقة أرضية تظهر في التقرير وتؤثر على micro precision، لكن AP لها `null` فلا تدخل متوسط AP.
- `mask` اختياري، ومصفوفتاه بطول width×height بترتيب الصفوف. القيم أرقام فئات صحيحة غير سالبة. يجب استخدام الأبعاد ونظام الوسم نفسيهما، وnearest-neighbor عند تحجيم وسوم الفئات. تُجمع البكسلات لكل فئة أولًا ثم يؤخذ المتوسط عبر الفئات الموجودة في الحقيقة أو التوقع؛ لا يختفي FP لفئة غير موجودة في الحقيقة.
- وجود ignore في **الحقيقة** يستثني البكسل. توقع ignore فوق بكسل صالح يُعد خطأ. الأقنعة ذات كل البكسلات المستثناة تعيد `null` ولا تمنح IoU=1.

يمكن إضافة حقل `timing` مستقل، بقيم حقيقية فقط:

```text
timing.inferenceMs: مصفوفة أزمنة الاستدلال بعد الإحماء
timing.captureToSpeechMs: مصفوفة الالتقاط حتى بدء الصوت المسموع، إن قيس فعليًا
timing.measurementDurationMs: مدة الجلسة المقيسة بالملي ثانية
timing.framesProcessed: عدد إطارات مختلفة اكتمل تحليلها خلال المدة
```

لا يكفي وقت استدعاء speechSynthesis لتمثيل بداية الصوت المسموع، ولا يكفي تحديث aria-live لإثبات موعد قراءة VoiceOver/TalkBack. يستخدم ملخص الزمن nearest-rank؛ القياسات الغائبة تبقى `null`. لا تصنع الأداة IDF1/HOTA أو بطارية أو معدلات أحداث أرضية من بيانات لا تتضمنها؛ تُقاس بأدوات مستقلة وتربط بالتقرير.

## بوابات قبول مقترحة للمراجعة

**هذه قيم اقتراح هندسي أولي، لم يعتمدها مختص ولم تتحقق ميدانيًا. ليست حدود سلامة معيارية، ولا تعني صلاحية المشي المستقل حتى لو تحققت.** يراجع اختصاصي O&M والمشاركون تعريف الأحداث والعبارات والأحجام والعينات قبل تثبيتها.

| المجال | اقتراح بوابة مختبر/تجربة مضبوطة | شرط تفسيرها |
| --- | --- | --- |
| تسمية الأشياء | precision ≥ .90 وrecall ≥ .80 لكل فئة مدعومة معلنة؛ نشر فواصل الثقة | الأجسام الصغيرة والحجب والضوء الضعيف شرائح مستقلة؛ لا إخفاء فشلها بالمتوسط |
| تبديل النموذج | تحسن mAP50:95 بمقدار .02 على الأقل، دون تدهور recall للفئات الحرجة > .02، ودون تدهور p95 > 10% | يُفضّل فاصل ثقة paired يدعم التحسن؛ إن لم يُثبت التوازن يبقى Lite0 |
| تجزئة الأرضية | IoU ≥ .75 وDice ≥ .85 لفئة الأرض على كل شريحة رئيسية | الأرض المصنفة ليست مسارًا مضمونًا؛ لا تتحول العتبة إلى تصريح سير |
| قرائن خطر أرضي | recall أحداث ≥ .90 وfalse warnings ≤ 1/دقيقة على البروتوكول المحدد | قياس الظلال واللمعان والأنماط منفصل؛ أي فئة بلا بيانات تبقى غير مثبتة |
| التتبع | ≤ 1 تبديل هوية/دقيقة في المشاهد المضبوطة؛ إسقاط الهوية عند فقدها | لا تقييم حقيقي دون ground-truth track IDs |
| الاقتراب التجريبي | لا تنبيه «اقتراب قوي» في ≥ 95% من مقاطع الدوران/zoom/الحركة الجانبية السالبة | metric للأخطاء في التجربة؛ ليست ضمانًا خارجها |
| الاستجابة | p95 للاستدلال ≤ 250ms وللالتقاط حتى الصوت ≤ 1500ms | تُقاس على كل هاتف؛ لا تعد تلك الأزمنة مناسبة تلقائيًا للأخطار السريعة |
| التقادم | صفر استخدام معروف لإطار خارج TTL المعلن أو بعد توقف الجلسة في اختبارات fault injection | فشل واحد يمنع ترقية تلك النسخة |
| الصوت والإتاحة | صفر رسالة مزدوجة عبر القناتين في الحالات المختبرة؛ 100% من عناصر التحكم الأساسية قابلة للوصول | مراجعة فعلية VoiceOver/TalkBack، لا فحص DOM فقط |
| ثبات الجلسة | جلسة 20 دقيقة بلا crash؛ لا نمو مستمر غير مفسر للذاكرة؛ ميزانية بطارية تُثبت بعد baseline | لا توجد عتبة بطارية مزعومة من متصفح سطح المكتب |

## مصفوفة الهاتف والمتصفح

يلزم iPhone Safari مع VoiceOver، وAndroid Chrome مع TalkBack على جهاز متوسط وآخر محدود الموارد، مع تسجيل الطراز/OS/نسخة المتصفح. المحاكاة في Chrome المكتبي لا تحل محل أي صف.

لكل هاتف: تحميل بارد، تحميل cache، بدء/إيقاف 20 مرة، 5 دقائق إحماء موثقة، جلسة 20 دقيقة، دوران رأسي/أفقي، تبديل العدسة، خروج التطبيق للخلفية والعودة، حجب الكاميرا، رفض الإذن، انقطاع الشبكة، تفعيل/تعطيل قارئ الشاشة، وتزامن طلب Forge بطيء مع الكشف المحلي. تُجرى جلسة البطارية المقارنة بالسطوع والحرارة ووضع الطاقة نفسيهما. تُذكر القيود التي لم تدعم أداة الجهاز قياسها.

يُقاس وقت الالتقاط من `capture timestamp`، لا من انتهاء الاستدلال. يُسجل rejected/dropped frames والسبب. تُفصل جودة الكشف المحلي عن نجاح الشبكة؛ الخطأ السحابي لا ينبغي أن يبقي نتيجة قديمة على أنها حيّة. لا تُرسل اللقطة دون موافقة مناسبة، ولا يُستخدم اتصال إنتاج لتجربة تغيّر بيانات المستخدمين.

## بروتوكول مراجعة O&M والمشاركين

1. **قبل التجنيد:** مراجعة الأهداف والعبارات ووسيلة الإيقاف مع اختصاصي توجه وحركة، وتحديد الموافقات البحثية اللازمة للجهة. حق الانسحاب والتعويض والموافقة بلغة وصيغة متاحتين.
2. **مراجعة ثابتة:** يختبر بالغون مكفوفون وضعاف بصر مهام «أين الكرسي؟/ما إلى اليمين؟/كرر/أوقف». يختبر فهم حدود الكاميرا وعدم مساواة «لم يرصد» بـ«آمن» دون السير قرب خطر.
3. **مسار مضبوط:** ممر خال من الخطر الفعلي، عوائق لينة، مراقب قادر على التدخل، واستخدام العصا/وسيلة التنقل المعتادة. تُوازن أسبقية baseline/candidate لتقليل أثر التعلم وتُمنح استراحات.
4. **الدرج/الحفر:** تقييم الرؤية أولًا بتسجيلات وصور وهاتف يحمله باحث. أي مشي لاحق يتطلب مراجعة منفصلة وحواجز ومراقبين؛ لا يُطلب الاقتراب من حفرة أو حافة بلا حماية لاختبار تنبيه.
5. **قياسات التجربة:** فهم الرسالة وإكمال المهمة وتكرار طلب المساعدة وعبء الكلام، الأخطاء والتدخلات والتوقفات، وإمكان سماع المحيط. تُسجل تفضيلات اللغة والقناة دون تعميم على جميع المكفوفين.
6. **إيقاف فوري:** يطلبه المشارك، أو ضيق/دوار/تعب، أو فشل الكاميرا، أو عبارة توهم بخلو طريق، أو توجيه معاكس، أو تأخر يفقد الرسالة معناها. لا تُواصل الجولة لجمع مزيد من الأرقام بعد ظهور شرط الإيقاف.
7. **المراجعة:** تحليل مستقل لكل فشل والتمييز بين نموذج/كاميرا/تتبع/صوت/واجهة. الترقية إلى بيئة أوسع قرار جديد مشروط؛ نجاح الممر لا يجيز شارعًا أو درجًا عامًا.

تستند طريقة البدء المضبوط وإشراك المستخدمين إلى [Wayfindr Open Standard](https://www.wayfindr.net/open-standard)، وتراعي دور مهارات التنقل كما توضحه [RNIB](https://www.rnib.org.uk/documents/73/Understanding_how_blind_and_partially_sighted_people_get_around_-_RNIB_2021.pdf). التطبيق المقترح للبروتوكول مسؤولية الدراسة المحلية ولم يحدث في هذه المراجعة.

| تشغيل Lite0 على صورة مكتبية متكررة | benchmark موجود بالمستودع؛ إن نُفذ فهو زمن استدلال محدود، وليس precision/recall |
| مجموعة مستقلة موسومة + تشغيل baseline/candidate | غير متوفرة ضمن هذه الوثيقة |
| مقاييس حفر/سلالم/أسلاك حقيقية | لم تُقَس هنا |

| بطارية وذاكرة هاتف وحرارة | لم تُقَس هنا |
| مشاركون مكفوفون ومراجعة O&M | لم تُنفَّذ/تعتمد هنا |
| السماح بالنشر التجاري لكل وزن | يحتاج سجل مصدر وترخيص؛ قيد SegFormer موثق في بحث E1 |

يجب أن تتضمن حزمة التقرير: manifests وhashes، سجل الوسم، لقطات النتائج بعد إزالة البيانات الشخصية، ملف JSON المقاييس، إعدادات التشغيل، الجهاز والمتصفح، منحنيات precision/recall، شرائح الفشل، النتائج المفقودة، واسم المراجع وتاريخ موافقته عند حصولها. لا تُحوّل `null` إلى صفر أو إلى عبارة «نجح».
