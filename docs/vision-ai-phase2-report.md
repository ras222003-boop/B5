## الاختبارات

جميع الآتي نُفذ محليًا بعد تغييرات المرحلة الثانية، مع [بصمات الملفات والسجلات](vision-ai-evidence/phase2-validation.json):

- **43** اختبار Node للأدوات: تشمل الخصوصية والحقوق والتكرار وتسرب التقسيم والمسافة/الامتناع والحركة والتخزين وCOCO والتقييم والإصدارات.
- **6** اختبارات Python للتحضير: اعتماد التدريب وفحص GPU ورفض البيانات الاصطناعية قبل استيراد ML، دون تدريب.
- **461** اختبار تطبيق في **82** ملف Vitest.
- **17** اختبار perception وauto-meter.
- TypeScript بلا أخطاء؛ build ناجح مع تحذير أحجام chunks الموجود مسبقًا.
- `git diff --check` وفحص CLI وأسماء/محتوى الملفات الصادرة: ناجحة.

الإجمالي **527 اختبارًا**. الاختبارات الاصطناعية تختبر الحسابات والحواجز، ولا تقيس دقة النموذج على العالم الحقيقي. اختبارات FFmpeg الحالية تستخدم محاكاة للعملية؛ FFmpeg/ffprobe غير متاحين في PATH، ولم يجر استخراج فيديو حقيقي. أدلة browser smoke من المرحلة الأولى تظل أدلة عقد اصطناعية فقط؛ لم يُعَد قياس هاتف أو نموذج SSDLite مدرب في هذه المرحلة.

فحص البيئة الفعلي: Python 3.12.14، torch 2.5.1+cpu، torchvision 0.20.1+cpu، CUDA غير متاح وready=false. البيئة المقترحة Python3.11/torch2.7.1/torchvision0.22.1 مستقلة؛ لم تُثبت أو يُنزّل checkpoint للتدريب دون بيانات. نجاح preflight واختبارات الحواجز لا يثبت نجاح دورة تدريب وتصدير على GPU.

## تدقيق الملفات والخصوصية

فحص المرحلة الأولى شمل 529 ملفًا نصيًا متتبعًا و26 ملفًا صادرًا. لم يظهر سر أو وسيط خاص في الملفات الصادرة. تطابقات AWS الشكلية كانت في Base64 الخاص بـTesseract WASM القديم، لا في ملفات التغيير. فحص النشر القابل للتكرار يفحص الملفات الصادرة للأنماط الحساسة والوسائط والأوزان وملفات البيانات/الموافقات. هذا فحص أنماط ومراجعة للكود، وليس ضمانًا لاكتشاف كل سر ممكن.

لم تُضف صور أو فيديوهات أو حقوق خاصة أو checkpoints إلى Git. التخزين الحقيقي فارغ من الوسائط، وخارج المستودع. بيانات اختبارات الوحدات مولدة مؤقتًا وتُحذف، ولا تصلح كبيانات تدريب أو حقوق مرخصة حقيقية. الإقرارات البشرية للحقوق والخصوصية والمعايرة ضرورية؛ SHA يثبت هوية الملف، لا صحة الإقرار.

## الخطوة التالية

اتبع [دليل إضافة الملفات والأوامر الكاملة](../ml/vision/PHASE2.md)، و[احتياجات البيانات لكل فئة](vision-ai-data-requirements.json). البداية: صور وفيديوهات فريق/مرخصة، أدلة الحقوق لكل ملف، جلسات مستقلة، وسوم يراجعها شخص آخر، قياسات إلى أقرب سطح ظاهر، فيديوهات controls للدوران والزوم، ومجموعة اختبار محجوزة.

الموارد المقترحة كتقدير أولي: NVIDIA GPU بذاكرة12–16GB، RAM32GB، نحو8vCPU، و150–250GB تخزين خاص ونسخة احتياطية منفصلة. للمحاولة الأولى على10,000 صورة و5epochs وbatch4 خطط مبدئيًا2–6ساعات GPU، ثم استبدل الافتراضات بقياس الزمن والذاكرة الفعلي. لا خدمة مدفوعة أو GPU أو bucket حُجزت أو أُنشئت.

قبل أول تدريب: اجمع وراجع البيانات، جمّد التقسيم، صدّر COCO، جهز وزنًا مرخصًا محليًا، افحص GPU، أنشئ approval.pending.json، ثم يعتمدها مراجع البيانات ومراجع التدريب المختلفان. شغّل preflight-only أولًا ثم train --device cuda. تدريب الحركة/العمق/الأسطح وتوليد التنبيهات الصوتية يحتاج تجارب مستقلة لاحقة؛ SSDLite الحالي يدرب صناديق الكشف فقط.

قبل أي إحلال للنموذج: مقارنة مستقلة بنفس بروتوكول النموذج الحالي، فحص regressions حسب الفئة والإضاءة والحجم، تكافؤ التصدير والمتصفح على صور حقيقية، اختبار الجوال الحراري وFPS والتتبع، ومراجعة السلامة. لا تُفعّل مؤشرات اقتراب أو فئات قرب مترية أو تعليمات سير اعتمادًا على الكاميرا وحدها. النشر والدمج يظلان بحاجة إلى موافقة المستخدم.
